# Framework Genérico V5.1.0 · Integral Autosostenido v1.0

**Fecha:** 2026-10-06  
**Estado:** ESTABLE · núcleo portable de incorporación  
**Propósito:** permitir incorporar y continuar el Framework en un proyecto real sin depender permanentemente de la aplicación, del repositorio maestro o del autor original.

## 1. Identidad

```text
PERFIL = lente
FRAMEWORK = espacio operativo
PROBLEMA = centro
```

El Framework es un sistema sociotécnico-transdisciplinario evolutivo que articula comunidad, prácticas, conocimiento, tecnología, IA, memoria, gobernanza y problemas reales.

## 2. Autosostenibilidad

Un proyecto debe poder:

```text
entender
→ activar
→ usar
→ documentar
→ continuar
→ verificar
→ transferir
```

sin dependencia permanente de una aplicación o repositorio externo.

## 3. Modos

- **START:** proyecto nuevo.
- **INTEGRATE:** proyecto existente al que se incorpora el Framework sin colonizar su estructura.
- **AUDIT:** proyecto existente que requiere contraste de estado, evidencia, decisiones e historia.

## 4. Macroestructura común

00–21 + 99 es la gramática común. Se materializa proporcionalmente.

```text
macroestructura lógica siempre disponible
→ áreas físicas solo cuando existe necesidad
```

## 5. Perfiles

- **PH:** construcción tecnológica humanista situada.
- **IT:** pregunta + método + evidencia + interpretación + responsabilidad epistemológica.
- **AT:** percepción situada + imaginación crítica + configuración sensible-simbólica-material + interpretación + transformación responsable.

Una Base de Conocimiento común puede ser invocada desde múltiples lentes.

## 6. Marco Pedagógico transversal

Seis principios:

1. situación antes que abstracción;
2. participación antes que consumo;
3. mediación proporcional para capacidad colectiva creciente, con autonomía y responsabilidad humanas preservadas;
4. reflexión trazable sobre la acción;
5. memoria compartida para aprendizaje colectivo;
6. transferencia y evolución como prueba de aprendizaje.

Ciclo:

```text
SITUAR
→ PARTICIPAR
→ MEDIAR
→ PRODUCIR
→ REFLEXIONAR
→ RECORDAR
→ TRANSFERIR
→ EVOLUCIONAR
↺
```

## 7. Humano · máquina · IA

```text
Humano    → propósito, interpretación, juicio, autorización y responsabilidad material
Máquina   → ejecución, persistencia, pruebas, logs y evidencia
IA        → análisis, síntesis, contraste, exploración y alternativas
Framework → estructura, contratos, memoria y gobernanza
```

La distribución puede variar por contexto, pero la autoridad material final permanece atribuible a humanos.

## 8. Caleidoscopio

No es un cuarto perfil ni una suma automática.

Puede reconocerse cuando existen simultáneamente:

- situación real;
- pluralidad de lentes;
- contraste real;
- emergencia nueva;
- trazabilidad.

## 9. Memoria

```text
Base de Conocimiento común = patrimonio epistemológico
Conocimientos activos       = estado presente
PORTAFOLIO                  = historia de uso, decisiones y cambios
```

```text
corregir != borrar
revisar != reescribir el pasado
```

## 10. Paquete de proyecto

La instancia portable mínima puede conservar:

- identidad y versión;
- modo;
- problema, contexto y propósito;
- perfiles y madurez;
- PORTAFOLIO;
- decisiones;
- transferencias;
- conocimiento invocado;
- eventos caleidoscópicos;
- schemas y continuidad.

La aplicación puede crear, leer, actualizar y reimportar este estado, pero el paquete debe seguir siendo inteligible fuera de la app.

## 11. Repositorios

```text
Repositorio maestro
= fuente canónica del Framework

Repositorio del proyecto
= fuente versionada de verdad de la implementación
```

GitHub es una infraestructura útil, no un requisito del dominio.

## 12. Transferencia simétrica reversible

```text
proyecto
→ aprendizaje candidato
→ procedencia + evidencia
→ contraste
→ gate humano
→ posible retorno al Framework
```

El aprendizaje transferido debe preservar contexto, límites y reversibilidad.

## 13. Regla de activación

No se activa todo.

```text
problema
→ necesidad
→ perfil/capacidad
→ profundidad proporcional
→ evidencia
→ revisión
```

## 14. Continuidad

Este núcleo es suficiente para orientar una implementación. La aplicación pública, las guías humanas, los schemas y el repositorio maestro amplían la experiencia sin convertirse en dependencias obligatorias.

## 15. Límites

V5.1.0 no afirma todavía:

- efectividad pedagógica general demostrada;
- comunidad de práctica madura;
- emergencia caleidoscópica empíricamente validada de forma general;
- métricas cuantitativas definitivas.

Estas afirmaciones requieren uso real y evidencia.
