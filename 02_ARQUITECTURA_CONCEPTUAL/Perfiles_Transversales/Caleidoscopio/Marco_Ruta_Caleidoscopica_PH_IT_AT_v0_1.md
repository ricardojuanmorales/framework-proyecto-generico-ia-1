## 1. Propósito

Este marco de ruta establece la arquitectura filosófico-operativa para desarrollar, vincular y activar los tres perfiles simétricos originales del Framework Genérico V4.1.1:

```text
Programador Humanista
Investigador Transdisciplinario
Artista Transdisciplinario
```

El propósito principal es clarificar cómo estos perfiles pueden operar individualmente o de manera caleidoscópica, compartiendo una misma estructura documental, una base de conocimientos común, una progresión N1-N4 y una bitácora de transferencia reversible.

El Programador Humanista v3.0.0 se desarrolla primero como perfil piloto. No se define como centro jerárquico del sistema. Su función es estabilizar un patrón maestro que pueda transferirse luego al Investigador Transdisciplinario y al Artista Transdisciplinario con igual dignidad estructural.

---

## 2. Principio rector

La tríada PH-IT-AT no funciona como cadena lineal ni como jerarquía disciplinaria. Funciona como sistema de perfiles equivalentes que se activan según el problema común, el nivel de complejidad del proyecto y la necesidad de integrar función técnica, evidencia investigativa y experiencia artístico-cultural.

```text
No hay perfil central fijo.
El centro operativo es el problema común.
Los perfiles se activan según necesidad.
La integración ocurre mediante curaduría transdisciplinaria.
La continuidad se preserva mediante bitácora reversible.
```

---

## 3. Perfiles simétricos originales

| Perfil | Función principal | Pregunta guía | Producto característico |
|---|---|---|---|
| Programador Humanista | Construye, adapta y documenta artefactos funcionales | ¿Qué puede implementarse de forma útil, segura, ética y documentada? | Aplicaciones, protocolos técnicos, guías de uso, prompts, herramientas, documentación |
| Investigador Transdisciplinario | Estudia, valida y metodologiza procesos y evidencias | ¿Qué puede observarse, analizarse, validarse y transferirse como conocimiento? | Preguntas, métodos, instrumentos, evidencias, análisis, publicaciones |
| Artista Transdisciplinario | Diseña mediaciones, experiencias, lenguajes y formas sensibles | ¿Cómo se vive, se comunica, se representa y se transforma la experiencia? | Narrativas, interfaces, visualizaciones, mediaciones, guiones, experiencias multimodales |

---

## 4. Modalidades de trabajo

### 4.1 Modalidad individual

Un perfil trabaja un problema, producto o proceso desde su lente propio.

```text
PH desarrolla una guía técnica.
IT diseña un instrumento de investigación.
AT crea una mediación visual, narrativa o experiencial.
```

La modalidad individual debe conservar documentación, seguridad, trazabilidad y posibilidad de transferencia posterior.

### 4.2 Modalidad caleidoscópica

Dos o tres perfiles atienden un mismo problema común de forma sistémica, holística y transdisciplinaria.

| Modalidad | Perfiles activados | Tercer lente |
|---|---|---|
| Dual PH-IT | Programador Humanista + Investigador Transdisciplinario | AT como lente latente |
| Dual PH-AT | Programador Humanista + Artista Transdisciplinario | IT como lente latente |
| Dual IT-AT | Investigador Transdisciplinario + Artista Transdisciplinario | PH como lente latente |
| Triádica completa | PH + IT + AT | No aplica lente latente |

---

## 5. Problema común como punto de partida

Todo proyecto caleidoscópico comienza por el problema común, no por el perfil que convoca.

```text
Problema común
→ determina complejidad
→ define nivel N1-N4
→ activa perfiles necesarios
→ establece productos esperados
→ identifica lentes latentes
→ abre bitácora reversible
→ produce curaduría transdisciplinaria
```

El problema común debe formularse con amplitud suficiente para permitir lectura técnica, investigativa y artístico-cultural.

---

## 6. Progresión N1-N4 común

Los niveles N1-N4 son comunes a los tres perfiles. Representan madurez operativa, no identidad disciplinaria.

| Nivel | Madurez operativa | Descripción general |
|---|---|---|
| N1 | Exploración guiada | Comprensión inicial, uso asistido, productos simples, baja automatización |
| N2 | Producción asistida | Uso de plantillas, guías, prompts, flujos básicos y documentación inicial |
| N3 | Integración avanzada | Automatización parcial, evaluación, trazabilidad, productos compuestos |
| N4 | Ecosistema gobernado | Automatización agéntica, integración multi-perfil, gobernanza robusta, sostenibilidad |

---

## 7. Tres capas de nivelación

Para estudiar progreso y evolución se separan tres capas:

```text
Nivel del usuario
Nivel del proyecto
Nivel del producto
```

El nivel principal del caleidoscopio se define por la complejidad del proyecto. El nivel del usuario permite ajustar el andamiaje. El nivel del producto permite evaluar la madurez real de los artefactos.

---

## 8. Regla de progresión simétrica

Aunque usuario, proyecto y producto se midan por separado, los perfiles activados deben avanzar de forma simétrica.

```text
La simetría no significa producir lo mismo.
La simetría significa operar con madurez equivalente.
```

Ejemplo:

```text
Proyecto caleidoscópico N3
PH debe producir artefactos o protocolos N3.
IT debe producir evidencia, método o evaluación N3.
AT debe producir mediación, experiencia o análisis expresivo N3.
```

En activaciones duales, el tercer perfil aparece como lente latente calibrado al mismo nivel.

---

## 9. Lente latente

Cuando un proyecto activa solo dos perfiles, el tercer perfil no desaparece. Queda como lente latente con sugerencias mínimas de integración.

El lente latente debe:

```text
mantener presencia conceptual;
evitar puntos ciegos;
hacer preguntas de integración;
sugerir riesgos o posibilidades;
no exigir un producto completo;
estar calibrado al nivel N1-N4 del proyecto.
```

---

## 10. Curaduría transdisciplinaria

La curaduría transdisciplinaria será el mecanismo de integración final de proyectos caleidoscópicos.

En esta etapa inicial se crea como documento base:

```text
Protocolo_Curaduria_Transdisciplinaria_v0_1.md
```

Este protocolo comienza como base de discusión y podrá consolidarse más adelante cuando los tres perfiles estén maduros.

---

## 11. Base de conocimiento común

La Fase 2 debe construir una base de conocimiento común para la tríada. No debe ser tres bibliotecas separadas, sino una base compartida con secciones especializadas y enlaces reversibles.

La base común debe permitir invocar documentos a necesidad:

```text
guías;
plantillas;
protocolos;
prompts;
fichas de herramientas;
matrices;
rúbricas;
bitácoras;
documentos oficiales de aplicaciones;
criterios de seguridad;
criterios de transferencia.
```

---

## 12. Fases espirales comunes

| Fase | Función dentro de la espiral |
|---|---|
| Fase 1 | Paquete rector del perfil |
| Fase 2 | Base de conocimientos común |
| Fase 3 | Capacidades N1 |
| Fase 4 | Capacidades N2 |
| Fase 5 | Capacidades N3 |
| Fase 6 | Capacidades N4 |

Las Fases 3 a 6 trabajan metodologías, prompts, herramientas, documentos de uso, protocolos, productos tangibles, evaluación y transferencia reversible. La diferencia no es el tipo general de producto, sino el nivel de madurez operativa.

---

## 13. Función del Programador Humanista como perfil piloto

El PH v3.0.0 se desarrolla primero porque permite estabilizar el patrón documental, metodológico y operativo del sistema.

```text
crear el primer molde completo;
probar la estructura de fases;
definir productos tangibles;
activar seguridad longitudinal;
ensayar transferencia reversible;
preparar la futura simetría con IT y AT.
```

PH no debe convertirse en centro fijo del ecosistema.
