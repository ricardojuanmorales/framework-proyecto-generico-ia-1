**Estado:** aprobado por humano  
**Rama de origen:** `fase2-operacionalizacion-v5`

## 1. Decisión

Se aprueba el cierre conceptual de Fase 2.

1. Contrato de Activación;
2. Modelo Operacional N1–N4;
3. Contrato de Orquestación PH–IT–AT + Caleidoscopio;
4. Contrato de Invocación de Métodos y Conocimiento;
5. Modelo Portable de Proyecto + Portafolio + Schemas;
6. Onboarding Dual Usuario + Colaborador;
7. Contrato de Release V5 + MVP;
8. Auditoría de Coherencia Interna;
9. Mapa Rector Operacional de Fase 2.

## 2. Estado de Fase 2

```text
Fase 2
= conceptualmente cerrada
```

No quedan contradicciones materiales abiertas que impidan construcción.

## 3. Apertura de Fase 3

Se autoriza iniciar Fase 3 bajo cuatro movimientos:

```text
CONSTRUIR
→ INTEGRAR
→ VERIFICAR
→ PUBLICAR
```

## 4. Capa metodológica longitudinal

Fase 3 queda gobernada transversalmente por:

```text
SDD
+ Local-first
+ Security by Design
+ Security by Default
+ Human-centered AI
+ Reversibilidad
+ Portabilidad
+ Trazabilidad
+ Verificación reproducible
```

## 5. SDD

SDD permanece como método invocable dentro del Framework.

Para la construcción de la aplicación V5 se selecciona explícitamente como método de desarrollo PH.

```text
SDD
!= nueva competencia PH
!= obligación universal del Framework

SDD
= método de construcción seleccionado para la aplicación V5
```

## 6. Primer movimiento

Fase 3 no comienza por código ni por elección de stack.

Comienza por:

```text
Spec Rectora V5
→ arquitectura técnica
→ contratos técnicos
→ implementación
```

## 7. Gates humanos

Se conservan tres gates humanos principales:

- H3-A: Spec Rectora + arquitectura material;
- H3-B: autorización de v5.0.0-rc.1;
- H3-C: autorización de v5.0.0.

No se solicitará aprobación humana para cada microdecisión técnica salvo cambio material de alcance, riesgo o irreversibilidad.
