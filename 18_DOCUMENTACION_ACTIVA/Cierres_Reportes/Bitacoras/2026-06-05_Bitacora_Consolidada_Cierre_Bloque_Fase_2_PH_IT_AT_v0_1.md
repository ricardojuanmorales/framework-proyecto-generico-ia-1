---

## 2. Decisiones metodológicas principales

| Decisión | Resultado |
|---|---|
| Mantener registro de deuda como canvas activo | Evita versiones excesivas durante trabajo vivo |
| Exportar registro de deuda solo al cierre de bloque | Se crea v0.3 como fotografía formal |
| Usar referencias lógicas Tipo 1 | Se evita duplicación física editable |
| Usar sub-cartapacios específicos cuando existan | Se corrigieron rutas de rúbricas, seguridad y evolución |
| Validar rutas contra mapa estructural | Se reduce riesgo de rutas inventadas |
| Diferenciar carpeta, metadato, índice y referencia | Mejora gobernanza y futura base de datos |
| Crear glosario v0.2 con núcleo conceptual-operativo | El sistema ya tiene idioma propio |
| Bloquear agentes, workflows y CI/CD final | Seguridad longitudinal preservada |

## 4. Transferencia simétrica PH-IT-AT

La transferencia simétrica quedó fortalecida porque:

```text
1. PH opera como perfil piloto, no como centro jerárquico;
2. IT y AT pueden incorporarse después sin rehacer la arquitectura;
3. el conocimiento común queda separado del conocimiento específico;
4. el caleidoscopio puede invocar documentos mediante metadatos y referencias;
5. las fases futuras 3-6 podrán devolver productos a la base común o específica;
6. el nivel operativo mínimo protege combinaciones PH-IT-AT.
```
