## 2. Refinamientos aprobados como candidatos

### 2.1 SDD como método invocable

SDD no se añade como competencia ni como UN.

Se reconoce como ejemplo de **método invocable** capaz de orquestar varias competencias PH según contexto, riesgo y alcance.

Regla candidata:

> Un método invocable organiza cómo se ejercen capacidades existentes. No redefine por sí mismo la identidad del perfil.

SDD puede activar, entre otras:

- PH-C01;
- PH-C02;
- PH-C03;
- PH-C04;
- PH-C06;
- PH-C07;
- PH-C08.

---

### 2.2 Reversibilidad como principio transversal

Regla candidata:

> Una decisión, diseño o transferencia es reversible cuando declara estado, límites, condiciones de salida y trazabilidad suficiente para modificar, retirar, transferir o reabrir sin pérdida material de comprensión o control.

Aplica transversalmente a:

- arquitectura;
- decisiones;
- integración;
- deuda;
- mantenimiento;
- transferencia;
- reapertura.

No crea competencia, UN ni gate nuevo.

---

### 2.3 Documentación operacional

Refinamiento candidato para PH-C07:

> La madurez documental no se mide por volumen. Se mide por su capacidad para reducir ambigüedad, preservar decisiones, sostener verificación, facilitar continuidad y permitir reapertura.

La documentación madura debe mantener relación visible con al menos una de estas funciones:

- decisión;
- contrato;
- criterio de aceptación;
- prueba;
- riesgo;
- dependencia;
- versión;
- continuidad;
- transferencia.

---

### 2.4 Separación de funciones de autoridad

Se propone distinguir:

```text
ejecutar
→ producir una acción o transformación

verificar
→ comprobar contra criterios explícitos

interpretar
→ atribuir sentido a la evidencia

decidir
→ seleccionar una alternativa

autorizar
→ ejercer autoridad para permitir una acción o cambio

habilitar
→ dejar operativamente disponible el siguiente paso
```

Regla:

> La verificación automática puede informar una decisión, pero no sustituye autorización humana cuando un gate o cambio estructural la requiere.

---

## 3. Implicación sobre Bases de Conocimiento

Regla candidata:

> PH define capacidades y actuaciones. Las Bases de Conocimiento proveen conocimiento reusable e invocable para ejercerlas con métodos, criterios, límites y herramientas conceptuales.

Por tanto:

```text
competencia != metodología
competencia != documento
Base de Conocimiento != almacén
```

---

## 4. Implicación sobre transferencia

Regla candidata:

> Transferir función y razón antes que forma física.

La transferencia simétrica reversible debe priorizar:

- patrón;
- contexto;
- evidencia;
- método;
- criterio;
- límite;
- transformación.

No copiar topologías documentales por defecto.
