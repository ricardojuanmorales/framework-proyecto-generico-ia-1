# Plan de pago de deuda para operatividad del Framework V5 v1.0

**Fecha:** 2026-10-05  
**Estado:** APROBADO · ejecución autorizada  
**Objetivo:** dejar el Framework arquitectónica y operacionalmente preparado para producir evidencia real.

## Orden lógico de pago

### P0. Canon y registro
- integrar decisiones A-G;
- actualizar Marco Pedagógico;
- preservar bitácora y referencias cruzadas.

**Estado:** en ejecución.

### P1. Schema canónico de Base de Conocimiento
Definir unidad de conocimiento, procedencia, relaciones, perfiles, madurez, historial, usos e interpretaciones.

### P2. Migración controlada del repositorio bibliográfico
```text
inventario
→ reconciliación
→ transformación
→ validación
```

La migración debe ser reproducible, reversible y preservar historia.

### P3. Contrato técnico de invocación PH·IT·AT
Conectar problema/contexto, perfil, conocimiento invocado, propósito, interpretación, decisión/artefacto y consecuencia.

### P4. Gobernanza comunitaria operativa mínima
Definir propuesta, revisión, contraste, validación, integración, disenso, reapertura y cambios canónicos.

### P5. Instrumento ligero de verificación caleidoscópica
Registrar situación, lentes, conocimiento, contraste, emergencia, papel H/M/IA, trazabilidad y estado.

### P6. Superficies operativas mínimas
Habilitar consulta, activación de conocimiento, invocación, procedencia, relación con PORTAFOLIO y registro de emergencia candidata.

### P7. Verificación integral
- schemas;
- tests;
- roundtrip;
- portabilidad;
- procedencia;
- documentación;
- seguridad;
- accesibilidad;
- deuda residual.

### P8. Gate humano de preparación para uso real
Declarar listo para uso real controlado solo si los contratos y verificaciones son coherentes y la deuda restante está explícita.

## Deuda que debe esperar evidencia empírica

Se mantiene abierta deliberadamente:

1. comunidad de práctica efectiva;
2. validación pedagógica empírica;
3. evidencia de emergencias caleidoscópicas reales;
4. transferencia del aprendizaje en contextos nuevos;
5. indicadores de madurez comunitaria;
6. necesidad o no de métricas cuantitativas del Caleidoscopio.

## Principio

```text
pagar lo diseñable ahora
→ usar el Framework
→ producir evidencia
→ pagar solo después la deuda que depende de realidad
```
