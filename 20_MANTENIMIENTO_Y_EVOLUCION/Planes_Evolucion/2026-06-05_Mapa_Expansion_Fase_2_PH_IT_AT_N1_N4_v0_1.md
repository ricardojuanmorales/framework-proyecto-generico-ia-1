## 0. Propósito

Este mapa define una ruta de expansión gradual para la Fase 2 PH-IT-AT, desde un núcleo documental mínimo viable hasta un ecosistema preparado para bases de datos, tableros, automatización gobernada, agentes futuros, documentación humana avanzada y seguimiento N1-N4.

La expansión debe ser:

```text
robusta;
resiliente;
sostenible;
flexible;
segura;
trazable;
compatible con usuarios N1-N4;
compatible con PH, IT, AT y Caleidoscopio;
capaz de crecer sin crear caos documental.
```

---

## 1. Principio rector

```text
Empezar simple.
Documentar bien.
Complejizar solo cuando exista necesidad real.
Mantener seguridad y transferencia desde el inicio.
```

La Fase 2 no debe crear productos por ansiedad de arquitectura. Debe crear productos cuando estos ayuden a sostener conocimiento común, conocimiento específico, transferencia reversible, seguridad, evaluación o evolución futura.

## 7. Ruta hacia tablas y JSON

La transición hacia estructuras JSON o tablas debe ocurrir por etapas.

### Etapa 1 — Metadatos consistentes

```text
Completar campos mínimos en documentos.
Usar valores controlados.
Evitar rutas ambiguas.
```

### Etapa 2 — Tablas humanas

```text
Tabla de ubicación documental.
Tabla de documentos invocables.
Tabla de metodologías.
Tabla de herramientas.
Tabla de riesgos.
```

### Etapa 3 — JSON piloto

```text
Exportar documentos, términos, herramientas y metodologías en JSON.
Validar estructura.
Revisar privacidad.
```

### Etapa 4 — Base de datos futura

```text
Diseñar entidades.
Definir relaciones.
Migrar solo cuando el volumen lo justifique.
```

### Etapa 5 — Tableros

```text
Visualizar progreso, deuda, seguridad, niveles, documentos y productos.
```

## 14. Criterios para decidir cuándo complejizar

Complejizar solo si se cumple al menos una condición fuerte:

```text
1. el volumen documental ya no se maneja con índice y registros;
2. hay repetición que justifica plantilla o automatización;
3. hay evidencia de uso recurrente;
4. el riesgo exige control formal;
5. hay varios usuarios o perfiles interactuando;
6. se necesita seguimiento longitudinal;
7. se prepara despliegue público;
8. la deuda documental impide avanzar;
9. la evaluación requiere datos estructurados;
10. la gobernanza lo aprueba.
```

No complejizar si:

```text
1. solo se desea por elegancia técnica;
2. no hay usuarios o productos suficientes;
3. no hay seguridad validada;
4. el proceso humano todavía no está claro;
5. no existe documentación suficiente;
6. puede resolverse con una tabla simple.
```
