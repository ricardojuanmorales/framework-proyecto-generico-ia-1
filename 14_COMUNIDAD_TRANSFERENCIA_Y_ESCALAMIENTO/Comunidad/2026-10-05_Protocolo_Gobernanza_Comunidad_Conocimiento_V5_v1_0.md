# Protocolo de Gobernanza de Comunidad y Conocimiento V5 v1.0

**Fecha:** 2026-10-05  
**Estado:** APROBADO · operativo mínimo  
**Ámbito:** comunidad, Base de Conocimiento común, contribuciones y evolución.

## 1. Principio

La comunidad puede aprender, contribuir y ayudar a evolucionar el Framework, pero ninguna contribución adquiere autoridad por mera participación.

```text
aporte
→ revisión
→ contraste
→ validación
→ integración
```

## 2. Formas de participación

- **Aprender:** usar, comprender, practicar y registrar.
- **Contribuir:** aportar fuentes, casos, artefactos, crítica, evidencia, anotaciones o propuestas.
- **Evolucionar:** participar en revisión de prácticas, contratos, repertorio y cambios del Framework.

No son rangos jerárquicos ni credenciales automáticas.

## 3. Estados de una contribución

1. **proposed:** incorporada con procedencia;
2. **reviewed:** examinada por una persona o proceso competente;
3. **validated:** procedencia, fidelidad y pertinencia suficientemente contrastadas;
4. **reference:** aceptada para uso recurrente;
5. **superseded:** preservada históricamente, pero reemplazada total o parcialmente.

```text
superseded != borrado
```

## 4. Autoridad proporcional

La competencia necesaria para validar depende del tipo de afirmación y del riesgo.

- bibliografía: fidelidad y fuente primaria;
- evidencia empírica: método, datos y límites;
- arquitectura: coherencia técnica y reversibilidad;
- pedagogía: fundamento, evidencia y consecuencias formativas;
- arte: sentido, contexto, representación y responsabilidad;
- cambios canónicos: revisión humana explícita y gate reforzado.

No se exige que una sola persona valide todas las dimensiones.

## 5. Disenso

El desacuerdo defendible debe preservarse con razones y procedencia.

```text
desacuerdo != error
decisión != unanimidad
```

Cuando exista controversia:
- registrar posiciones;
- relacionar evidencia;
- declarar incertidumbre;
- documentar la decisión tomada;
- preservar posibilidad de reapertura.

## 6. Papel de IA y máquina

La IA puede organizar, resumir, contrastar, detectar duplicados y sugerir relaciones. La máquina puede persistir, validar estructuras y preservar evidencia.

No pueden por sí solas:
- conceder autoridad;
- cerrar controversias epistemológicas;
- elevar una entrada a canon;
- aprobar cambios materiales.

## 7. Cambio canónico

Todo cambio que modifique principios, arquitectura, autoridad o gobernanza requiere:

```text
problema/evidencia
→ propuesta
→ contraste
→ revisión pertinente
→ gate humano
→ versionado
→ memoria
```

## 8. Conflictos y reapertura

Una decisión validada puede reabrirse cuando:
- aparece nueva evidencia;
- se detecta error de procedencia;
- cambia el contexto material;
- emerge un riesgo no considerado;
- la práctica demuestra insuficiencia recurrente.

Reabrir no elimina la decisión anterior.

## 9. Criterio de suficiencia

Este protocolo es suficiente para iniciar uso real controlado. La distribución concreta de roles, cadencias y mecanismos de reconocimiento debe ajustarse con evidencia de comunidad real.
