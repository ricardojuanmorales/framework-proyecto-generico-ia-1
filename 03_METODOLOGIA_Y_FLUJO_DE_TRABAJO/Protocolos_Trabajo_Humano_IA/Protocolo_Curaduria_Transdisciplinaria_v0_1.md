## 1. Propósito

Este protocolo define una primera base para la curaduría transdisciplinaria de proyectos caleidoscópicos PH-IT-AT.

La curaduría transdisciplinaria es el mecanismo para integrar productos, criterios, tensiones y hallazgos generados por dos o tres perfiles simétricos ante un problema común.

Este documento no constituye versión final. Debe considerarse instrumento inicial de discusión que se consolidará cuando los tres perfiles tengan madurez suficiente.

---

## 2. Principio operativo

La curaduría transdisciplinaria no busca borrar las diferencias entre perfiles. Busca articularlas.

```text
PH aporta función, implementación, herramientas, documentación técnica y operación.
IT aporta evidencia, método, análisis, validez y conocimiento.
AT aporta experiencia, mediación, lenguaje, percepción, accesibilidad y sentido.
```

La síntesis no debe reducirse a suma de productos. Debe producir una lectura integrada, trazable y útil del problema común.

---

## 3. Cuándo activar curaduría

La curaduría debe activarse cuando ocurra al menos una condición:

```text
1. Un proyecto involucra dos o tres perfiles.
2. Un producto técnico requiere evaluación investigativa o mediación experiencial.
3. Un producto investigativo requiere herramienta, protocolo, visualización o interfaz.
4. Un producto artístico o mediacional requiere evidencia, documentación o soporte técnico.
5. Existe tensión entre utilidad, seguridad, validez, accesibilidad o sentido cultural.
6. Se requiere cerrar un ciclo de transferencia reversible.
```

## 4. Entradas mínimas

| Entrada | Descripción |
|---|---|
| Problema común | Formulación compartida del problema que activa el proyecto |
| Nivel N1-N4 del proyecto | Complejidad del proyecto |
| Perfiles activados | PH, IT, AT o combinación dual |
| Lente latente | Perfil no activado plenamente, si aplica |
| Productos por perfil | Artefactos, instrumentos, mediaciones, guías o evidencias |
| Riesgos | Seguridad, privacidad, datos, ética, representación, accesibilidad |
| Evidencias | Registros, pruebas, observaciones, bitácoras o trazas |
| Decisiones abiertas | Puntos que requieren deliberación |
| Transferencia reversible | Impacto de cada hallazgo hacia los demás perfiles |

## 5. Proceso mínimo de curaduría

### Paso 1. Formular el problema común

```text
¿Cuál es el problema común?
¿Por qué requiere uno, dos o tres perfiles?
¿Qué nivel de complejidad N1-N4 tiene?
```

### Paso 2. Identificar perfiles y lente latente

```text

```

### Paso 3. Recoger aportes por perfil

| Perfil | Aporte mínimo |
|---|---|
| PH | Artefacto, protocolo, guía, herramienta, prompt o documentación funcional |
| IT | Pregunta, método, evidencia, instrumento, análisis o criterio de validez |
| AT | Narrativa, mediación, interfaz, experiencia, lenguaje o criterio de accesibilidad/sentido |

### Paso 4. Identificar tensiones

```text
¿Hay tensión entre eficiencia técnica y seguridad?
¿Hay tensión entre evidencia disponible y afirmaciones del producto?
¿Hay tensión entre experiencia deseada y accesibilidad real?
¿Hay tensión entre automatización y revisión humana?
¿Hay tensión entre representación cultural y neutralidad instrumental?
```

### Paso 5. Aplicar gates G0-G7 según corresponda

| Gate | Pregunta curatorial |
|---|---|
| G0 Contexto y datos | ¿Quién participa, qué datos aparecen y qué límites deben respetarse? |
| G1 Arquitectura y diseño seguro | ¿Cómo está diseñado el flujo o artefacto? |
| G2 Codificación segura | ¿Hay prácticas técnicas o de implementación que revisar? |
| G3 Dependencias y secretos | ¿Hay paquetes, credenciales, fuentes o dependencias sensibles? |
| G4 Revisión y pruebas | ¿Existe revisión humana o evidencia mínima? |
| G5 Despliegue seguro | ¿Dónde se usará, publicará o desplegará el producto? |
| G6 Operación y respuesta | ¿Cómo se mantendrá, corregirá o retirará si falla? |
| G7 Transferencia y documentación | ¿Qué vuelve a PH, IT, AT y a la documentación activa? |

### Paso 6. Producir síntesis transdisciplinaria

La síntesis debe incluir hallazgos integrados, decisiones, tensiones no resueltas, impacto por perfil, recomendaciones, estado de seguridad y próxima acción.

### Paso 7. Registrar transferencia reversible

Todo cierre debe producir una nota de transferencia reversible.

---

## 6. Estados de curaduría

| Estado | Descripción |
|---|---|
| Inicial | Curaduría breve, exploratoria o N1 |
| Documentada | Curaduría con aportes y decisiones registradas |
| Comparativa | Curaduría que contrasta criterios entre perfiles |
| Integrada | Curaduría con síntesis, evidencias y recomendaciones |
| Gobernada | Curaduría con gates, revisión, trazabilidad y sostenibilidad |
| Pendiente | Falta información, evidencia o decisión |
| Bloqueada | Riesgo alto, conflicto no resuelto o ausencia de evidencia crítica |

## 8. Regla de seguridad

Ningún producto caleidoscópico debe declararse maduro si no documenta su estado de seguridad, privacidad, datos o justificación de no aplicación.
