# Contrato de Activación del Framework V5 v0.1

**Fecha:** 2026-09-22  
**Estado:** candidato Fase 2  
**Rama:** `fase2-operacionalizacion-v5`  
**Función:** definir la entrada mínima de un proyecto al Framework sin depender de conocimiento previo del repositorio.

---

## 1. Propósito

Convertir un problema real en una configuración inicial de trabajo suficientemente clara para comenzar sin sobrecarga documental.

El contrato gobierna tres modos:

```text
START
proyecto nuevo

INTEGRATE
proyecto existente

AUDIT
proyecto suficientemente maduro que desea contrastarse con el Framework
```

---

## 2. Entradas mínimas

Toda activación debe conocer solo:

1. problema o necesidad;
2. contexto;
3. personas o comunidades afectadas;
4. propósito esperado;
5. estado del proyecto: START / INTEGRATE / AUDIT;
6. restricciones conocidas;
7. riesgos iniciales;
8. artefactos o evidencia disponible, si existen.

No se exige al usuario conocer PH, IT, AT, N1-N4 ni la estructura 00–21 antes de comenzar.

---

## 3. Lo que propone el Framework

A partir de las entradas, el Framework puede **proponer**:

- perfil o perfiles pertinentes;
- posibles transferencias entre perfiles;
- madurez N1–N4 inicial;
- métodos invocables;
- fuentes de conocimiento federadas;
- gates aplicables;
- evidencias mínimas;
- siguiente bloque de trabajo.

Estas propuestas son situadas y revisables.

---

## 4. Lo que decide el humano

El humano conserva autoridad sobre:

- propósito del proyecto;
- aceptación o rechazo de lentes sugeridos;
- nivel de riesgo aceptable;
- activación de perfiles;
- decisiones estructurales;
- publicación;
- tratamiento de datos;
- cambios irreversibles o sensibles;
- cierre y transferencia.

Regla:

```text
Framework propone
máquina / IA asiste y verifica
humano autoriza lo material
```

---

## 5. Perfiles

### PH
Se activa cuando el problema requiere construcción, integración, mantenimiento o responsabilidad tecnológica situada.

### IT
Se activa cuando el problema requiere responsabilidad epistemológica sobre preguntas, método, evidencia, análisis, validez o incertidumbre.

### AT
Se activa cuando el problema requiere percepción situada, imaginación crítica, mediación, configuración sensible-simbólica-material, interpretación o transformación artística responsable.

### Combinación
Pueden actuar solos, en pares o triádicamente.

No existe obligación de activar los tres.

---

## 6. Caleidoscopio

No se selecciona como cuarto perfil.

Se reconoce posteriormente si la interacción entre dos o tres lentes produce una propiedad, pregunta, experiencia, artefacto o posibilidad que no estaba contenida plenamente en una sola lente.

```text
Caleidoscopio = posible emergencia
!= opción de activación
```

---

## 7. N1–N4 en activación

N1–N4 representan madurez operacional situada.

La activación registra, como mínimo:

- nivel aproximado del proyecto;
- nivel esperado del producto;
- nivel de autonomía disponible.

El nivel del usuario o equipo puede registrarse cuando sea útil.

La activación no congela el nivel.

```text
N1–N4 = hipótesis de trabajo revisable
```

---

## 8. Salida mínima

Toda activación debe producir una ficha compacta:

```text
modo: START / INTEGRATE / AUDIT
problema:
contexto:
propósito:
perfiles propuestos:
perfiles autorizados:
N1-N4 inicial:
métodos invocados:
conocimiento requerido:
riesgos:
gates:
evidencia inicial:
siguiente bloque:
decisiones humanas pendientes:
```

Esta ficha se convierte posteriormente en parte del estado portable del proyecto.

---

## 9. Relación con la plantilla histórica

La plantilla:

`07_PLANTILLAS_Y_MODELOS/Plantillas_Proyectos/Plantilla_Activacion_Proyecto_Caleidoscopico_v0_1.md`

se conserva como antecedente e instrumento detallado.

Este contrato la gobierna y la simplifica para V5.

Durante Fase 2 se decidirá si:

- se actualiza a una versión V5;
- se especializa por modo START / INTEGRATE / AUDIT;
- o se sustituye por un formulario generado por la aplicación.

No se crean tres plantillas separadas por defecto.

---

## 10. Criterio de activación suficiente

Un proyecto está suficientemente activado cuando puede responder:

```text
qué problema atiende
para quién
con qué propósito
qué lentes necesita
qué nivel de madurez estima
qué riesgos importan
qué conocimiento/métodos invocará
qué evidencia producirá
qué decisión humana viene después
```

No necesita completar toda la arquitectura documental del Framework antes de comenzar.

---

## 11. Antipatrón

Evitar:

```text
activar todos los perfiles
+
llenar todos los campos
+
crear todos los documentos
+
resolver toda la gobernanza
antes de hacer trabajo real
```

La activación debe habilitar movimiento, no convertirse en examen de entrada.

---

## 12. Criterio para Fase 2

Este contrato queda suficientemente estable cuando pueda ser usado por:

- una persona nueva;
- la aplicación V5;
- un proyecto existente;
- un proyecto nuevo;
- un auditor;
- una IA asistente;

y todos produzcan una salida compatible y comprensible.
