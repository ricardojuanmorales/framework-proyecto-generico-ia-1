## 0. Propósito

Esta taxonomía establece el sistema de categorías para organizar, estudiar, transferir e invocar la Base de Conocimiento PH-IT-AT de forma sistémica, holística y transdisciplinaria.

Su función es evitar que la base de conocimiento crezca como colección dispersa de archivos. La taxonomía permite clasificar cada documento, concepto, metodología, herramienta, evidencia, producto, nivel y ruta formativa por múltiples ejes complementarios.

La taxonomía será fundamento para:

```text
1. indexación documental;
2. glosario centralizado;
3. catálogos básicos;
4. rúbricas sistémicas y holísticas;
5. seguimiento de usuarios N1-N4;
6. transferencia simétrica PH-IT-AT;
7. invocación caleidoscópica dinámica;
8. seguridad longitudinal;
9. investigación sobre evolución del conocimiento;
10. futura migración a JSON, bases de datos, tableros y sistemas agénticos.
```

---

## 1. Principio rector

```text
No todo necesita una carpeta.
No todo necesita un documento independiente.
No todo conocimiento pertenece a un solo perfil.
No toda combinación debe predefinirse.

La taxonomía organiza relaciones.
Los metadatos registran esas relaciones.
Los índices permiten navegar.
El caleidoscopio emerge de combinaciones trazables.
```

---

## 2. Enfoque sistémico, holístico y transdisciplinario

### 2.1 Enfoque sistémico

La taxonomía considera cada documento como parte de un sistema de relaciones:

```text
documento
→ concepto
→ perfil
→ nivel
→ producto
→ evidencia
→ seguridad
→ transferencia
→ aplicación
→ actualización
```

No se clasifica un documento solo por su carpeta, sino por su función dentro del sistema.

### 2.2 Enfoque holístico

La taxonomía reconoce dimensiones humanas, éticas, técnicas, investigativas, creativas, educativas y operativas.

Cada elemento puede tener impacto en:

```text
aprendizaje;
accesibilidad;
seguridad;
experiencia;
evidencia;
implementación;
gobernanza;
sostenibilidad;
uso responsable de IA.
```

### 2.3 Enfoque transdisciplinario

La taxonomía no pertenece a una disciplina única. Integra:

```text
PH: función técnica, implementación, documentación, herramientas.
IT: evidencia, método, análisis, validez, investigación.
AT: experiencia, mediación, lenguaje, interfaz, narrativa.
Caleidoscopio: combinación dinámica según problema común.
```

## 3. Modelo general de clasificación

Cada pieza de conocimiento debe poder clasificarse por varios ejes. Los ejes no son carpetas obligatorias. Son categorías operativas e investigativas.

```text
Eje A: Función documental
Eje B: Tipo de conocimiento
Eje C: Perfil y modalidad
Eje D: Nivel N1-N4
Eje E: Ciclo de vida del conocimiento
Eje F: Evidencia y validación
Eje G: Seguridad, privacidad y riesgo
Eje H: Intensidad de IA y automatización
Eje I: Reusabilidad transversal
Eje J: Accesibilidad y andamiaje
Eje K: Invocación caleidoscópica
Eje L: Estado de transferencia
```

## 4. Eje A — Función documental

Este eje clasifica qué hace el documento.

| Código | Categoría | Descripción | Ejemplos |
|---|---|---|---|
| FUNC-GOB | Gobernanza | Define reglas, decisiones, límites, excepciones | protocolos, registros de decisión |
| FUNC-PLAN | Planificación | Organiza ruta, fases, alcance, secuencia | mapas, alcances, roadmaps |
| FUNC-BC | Base de conocimiento | Organiza conocimiento reusable | glosarios, catálogos, taxonomías |
| FUNC-MET | Metodología | Define cómo trabajar o investigar | protocolos, flujos, métodos |
| FUNC-PLANT | Plantilla | Permite producir documentos o productos | plantillas MD/JSON, proyectos |
| FUNC-EVAL | Evaluación | Permite valorar calidad o madurez | rúbricas, matrices, gates |
| FUNC-EVID | Evidencia | Registra validación, resultados, trazas | reportes, instrumentos, logs |
| FUNC-SEG | Seguridad | Atiende riesgos, privacidad, datos, IA | checklists, mapas de seguridad |
| FUNC-WIKI | Documentación humana | Explica para uso y aprendizaje humano | guías, FAQ, inicio rápido |
| FUNC-REF | Referencia lógica | Conecta sin duplicar físicamente | enlaces espejo, registros |
| FUNC-HIST | Archivo histórico | Conserva versiones cerradas | snapshots, versiones obsoletas |

## 7. Eje D — Nivel N1-N4

Este eje clasifica madurez por usuario, proyecto y producto. Los tres niveles deben registrarse por separado.

| Código | Nivel | Descripción |
|---|---|---|
| NIV-N1 | N1 | Exploración guiada, comprensión inicial, baja complejidad |
| NIV-N2 | N2 | Producción asistida, plantillas, flujos básicos |
| NIV-N3 | N3 | Integración avanzada, evaluación, trazabilidad, automatización parcial |
| NIV-N4 | N4 | Ecosistema gobernado, agentes futuros, auditoría, sostenibilidad |
| NIV-TODOS | Todos | Aplica a N1-N4 con andamiaje diferenciado |
| NIV-NA | No aplica | No se clasifica por nivel |

### 7.1 Regla acumulativa

```text
Cada nivel conserva acceso a las etapas del ciclo completo.
Cada nivel usa andamiajes, métodos, protocolos y evidencias apropiadas.
N4 no elimina N1; lo integra y lo gobierna.
```

## 18. Reglas de uso

```text
1. Clasificar por múltiples ejes, no por una sola categoría.
2. No convertir cada categoría en carpeta.
3. Usar metadatos para relaciones complejas.
4. Usar referencias lógicas para invocación.
5. Usar bitácora para decisiones y contexto.
6. Usar rúbricas para evaluación.
7. Usar seguridad como capa transversal.
8. Usar N1-N4 para andamiaje, no para restringir acceso conceptual.
9. Usar nivel mínimo en proyectos caleidoscópicos.
10. Actualizar la taxonomía cuando aparezcan usos nuevos sostenidos.
```
