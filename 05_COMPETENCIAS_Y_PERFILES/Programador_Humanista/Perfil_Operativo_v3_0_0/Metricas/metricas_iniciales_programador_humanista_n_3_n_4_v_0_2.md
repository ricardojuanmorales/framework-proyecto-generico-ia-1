## 1. Propósito del documento

Este documento define las **Métricas Iniciales N3/N4 del Programador Humanista v3.0.0**.

Su función es convertir el alcance, el mapa rector, la fórmula nuclear, la seguridad longitudinal, la transferencia triádica, las competencias y las unidades nucleares en criterios de evaluación observables.

Las métricas no buscan burocratizar la creación. Buscan evitar que un artefacto parezca maduro solo porque funciona una vez en una demostración amable. La madurez del Programador Humanista exige funcionamiento, evidencia, experiencia, seguridad, documentación, gobernanza, mantenimiento y transferencia.

---

## 2. Tesis de evaluación

El Programador Humanista se evalúa por la calidad integral de su proceso y de sus productos.

```text
Madurez PH = funcionalidad + evidencia + experiencia + seguridad + documentación + gobernanza + mantenimiento + transferencia
```

Un producto no alcanza N3 avanzado solo porque tenga código funcional. Debe poder ser comprendido, revisado, protegido, probado, documentado, mantenido y transferido.

Un producto no alcanza N4 emergente solo porque use herramientas avanzadas. Debe sostener arquitectura, trazabilidad, seguridad longitudinal, despliegue, observabilidad, auditoría, comunidad de uso y evolución.

---

## 3. Niveles de madurez evaluativa

| Nivel | Descripción general | Evidencia típica |
|---|---|---|
| N1 Exploración guiada | Comprende conceptos, sigue instrucciones y documenta aprendizaje inicial | notas, ejercicios, README simple, reflexión |
| N2 Producción asistida | Produce artefactos simples con apoyo de plantillas, IA o guía humana | prototipo, bitácora, checklist inicial |
| N3 Integración operativa | Integra técnica, IA, datos, seguridad, documentación, evidencia, experiencia y transferencia | aplicación funcional, repositorio, gates, matriz, pruebas, guías |
| N4 Ecosistema autosostenido | Sostiene arquitectura escalable, despliegue, monitoreo, gobernanza, auditoría y transferencia institucional | CI/CD, runbooks, observabilidad, auditoría, wiki humana, comunidad, releases |

---

## 4. Dimensiones maestras de evaluación

| Código | Dimensión | Pregunta rectora |
|---|---|---|
| M-PH-01 | Propósito humano y educativo | ¿El producto atiende una necesidad humana, educativa, investigativa o cultural clara? |
| M-PH-02 | Funcionalidad técnica | ¿El producto hace lo que declara hacer de forma verificable? |
| M-PH-03 | Arquitectura y pensamiento computacional | ¿La solución está organizada en componentes, flujos, dependencias y límites comprensibles? |
| M-PH-04 | IA responsable y colaboración humano-máquina | ¿La IA se usa con propósito, revisión humana, límites y trazabilidad? |
| M-PH-05 | Evidencia e investigación | ¿El producto produce, sostiene o permite analizar evidencia? |
| M-PH-06 | Experiencia, accesibilidad y mediación | ¿El producto cuida interacción, lenguaje, accesibilidad, narrativa y sentido? |
| M-PH-07 | Seguridad, privacidad y confianza longitudinal | ¿Integra seguridad por diseño, por defecto, gates, privacidad y controles mínimos? |
| M-PH-08 | Documentación viva y trazabilidad | ¿Otra persona puede entender, revisar y continuar el trabajo? |
| M-PH-09 | Gobernanza, decisiones y excepciones | ¿Registra decisiones, límites, riesgos, deuda y responsabilidades? |
| M-PH-10 | Mantenimiento, despliegue y evolución | ¿Tiene ruta de actualización, soporte, rollback, monitoreo o retiro? |
| M-PH-11 | Transferencia simétrica triádica | ¿Tiene lectura técnica, investigativa, artística y de seguridad? |
| M-PH-12 | Escalabilidad N4 | ¿Puede sostenerse en cursos, equipos, comunidades o instituciones? |

---

## 5. Escala común de evaluación

Toda dimensión puede evaluarse en una escala de 0 a 4.

| Puntuación | Estado | Descripción |
|---|---|---|
| 0 | Ausente | No hay evidencia o la dimensión no fue considerada |
| 1 | Declarado | Se menciona, pero no tiene evidencia suficiente |
| 2 | Documentado | Existe evidencia mínima, checklist, nota o decisión |
| 3 | Integrado | La dimensión afecta diseño, producción, evaluación y documentación |
| 4 | Longitudinal | La dimensión acompaña ciclo de vida, mantenimiento, revisión y transferencia |

### 5.1 Regla de no aplicación

Cuando una dimensión no aplique, debe registrarse como:

```text
No aplica, con justificación breve
```

Un “no aplica” sin justificación cuenta como ausencia documental.

## 6. Umbrales iniciales de madurez

| Nivel objetivo | Condición mínima |
|---|---|
| N1 | Promedio mínimo 1.0, sin riesgos críticos sin declarar |
| N2 | Promedio mínimo 1.8, documentación mínima y propósito claro |
| N3 inicial | Promedio mínimo 2.5, seguridad M2, transferencia T2, documentación viva |
| N3 avanzado | Promedio mínimo 3.0, gates aplicables, evidencia, arquitectura y seguridad integradas |
| N4 emergente | Promedio mínimo 3.5, despliegue, mantenimiento, observabilidad, gobernanza y transferencia longitudinal |
| N4 sostenido | Promedio mínimo 3.8, auditoría, comunidad, releases, mejora continua y escalamiento documentado |

### 6.1 Reglas de bloqueo

Un producto no debe declararse N3 avanzado si ocurre cualquiera de estas condiciones:

1. no identifica datos, usuarios o riesgos cuando aplica;
2. no tiene documentación mínima;
3. no tiene lectura de seguridad o justificación de no aplicación;
4. no puede ser entendido por otra persona fuera de la conversación original;
5. depende de IA sin revisión humana en decisiones relevantes;
6. no declara estado de transferencia triádica.

## 7. Métricas por dimensión

### 7.1 M-PH-01 Propósito humano y educativo

| Nivel | Evidencia observable |
|---|---|
| 0 | No hay propósito claro |
| 1 | El propósito se menciona de forma general |
| 2 | Identifica usuarios, contexto y problema |
| 3 | Alinea propósito, aprendizaje, evidencia, experiencia y límites |
| 4 | Demuestra impacto transferible, continuidad y utilidad comunitaria o institucional |

### 7.2 M-PH-02 Funcionalidad técnica

| Nivel | Evidencia observable |
|---|---|
| 0 | No funciona o no hay evidencia de funcionamiento |
| 1 | Funciona parcialmente en condiciones no documentadas |
| 2 | Funciona en un caso mínimo documentado |
| 3 | Funciona de forma reproducible con pruebas o revisión |
| 4 | Funciona con mantenimiento, monitoreo, versiones y continuidad |

### 7.3 M-PH-03 Arquitectura y pensamiento computacional

| Nivel | Evidencia observable |
|---|---|
| 0 | No hay estructura comprensible |
| 1 | Hay descripción general, pero sin componentes claros |
| 2 | Identifica componentes, entradas, salidas y dependencias |
| 3 | Incluye arquitectura modular, límites de confianza, datos y flujos |
| 4 | Ofrece arquitectura escalable, reusable, auditable y transferible |

### 7.4 M-PH-04 IA responsable y colaboración humano-máquina

| Nivel | Evidencia observable |
|---|---|
| 0 | Usa IA sin registro, límites ni revisión |
| 1 | Declara uso de IA de forma general |
| 2 | Registra prompts, decisiones o revisión humana básica |
| 3 | Integra IA en flujo reproducible, auditado y limitado |
| 4 | Diseña ecosistema humano-IA con gobernanza, evaluación y seguridad longitudinal |

### 7.5 M-PH-05 Evidencia e investigación

| Nivel | Evidencia observable |
|---|---|
| 0 | No produce ni conecta con evidencia |
| 1 | Sugiere evidencia posible sin instrumento claro |
| 2 | Incluye pregunta, instrumento, dato, corpus o matriz inicial |
| 3 | Integra método, trazabilidad, criterios y análisis preliminar |
| 4 | Produce evidencia transferible, replicable o publicable |

### 7.6 M-PH-06 Experiencia, accesibilidad y mediación

| Nivel | Evidencia observable |
|---|---|
| 0 | No considera experiencia ni accesibilidad |
| 1 | Menciona interfaz o público de forma general |
| 2 | Incluye criterios básicos de accesibilidad, lenguaje o mediación |
| 3 | Integra experiencia significativa, narrativa, participación y accesibilidad |
| 4 | Diseña experiencia multimodal, culturalmente situada, evaluada y transferible |

### 7.7 M-PH-07 Seguridad, privacidad y confianza longitudinal

| Nivel | Evidencia observable |
|---|---|
| 0 | Seguridad no considerada |
| 1 | Riesgos mencionados sin controles claros |
| 2 | Checklist o gate inicial aplicado |
| 3 | Gates, codificación segura, dependencias, secretos, privacidad y revisión integrados |
| 4 | SSDLC, DevSecOps, monitoreo, incidentes, auditoría y mejora continua |

### 7.8 M-PH-08 Documentación viva y trazabilidad

| Nivel | Evidencia observable |
|---|---|
| 0 | No hay documentación suficiente |
| 1 | Hay notas sueltas o documentación mínima incompleta |
| 2 | README, bitácora o changelog básico |
| 3 | Documenta arquitectura, decisiones, pruebas, seguridad y transferencia |
| 4 | Mantiene wiki, continuidad, gobernanza, archivo histórico y documentación multiusuario |

### 7.9 M-PH-09 Gobernanza, decisiones y excepciones

| Nivel | Evidencia observable |
|---|---|
| 0 | No registra decisiones ni responsabilidades |
| 1 | Menciona decisiones sin estructura |
| 2 | Registra decisiones, límites o riesgos principales |
| 3 | Integra registro de decisiones, excepciones, responsables y revisión |
| 4 | Opera con gobernanza viva, auditoría, revisión periódica y mejora institucional |

### 7.10 M-PH-10 Mantenimiento, despliegue y evolución

| Nivel | Evidencia observable |
|---|---|
| 0 | No hay ruta de continuidad |
| 1 | Lista próximos pasos de forma general |
| 2 | Define backlog, deuda técnica o soporte básico |
| 3 | Incluye versiones, release, runbook, rollback o mantenimiento |
| 4 | Integra observabilidad, incidentes, soporte, escalamiento y retiro responsable |

### 7.11 M-PH-11 Transferencia simétrica triádica

| Nivel | Evidencia observable |
|---|---|
| 0 | No hay transferencia |
| 1 | Declara posibles conexiones PH-IT-AT |
| 2 | Documenta equivalencias técnicas, investigativas y artísticas |
| 3 | Integra transferencia en diseño, evaluación, seguridad y documentación |
| 4 | Mantiene transferencia longitudinal en ciclo de vida, escalamiento y comunidad |

### 7.12 M-PH-12 Escalabilidad N4

| Nivel | Evidencia observable |
|---|---|
| 0 | No puede escalar o no se evaluó |
| 1 | Tiene potencial de escalamiento no documentado |
| 2 | Identifica condiciones mínimas para escalar |
| 3 | Incluye arquitectura, guías, mantenimiento y gobernanza para escalar |
| 4 | Opera como ecosistema replicable, auditable, sostenible y transferible |

## 10. Rúbrica compacta N3 avanzado

Un producto alcanza **N3 avanzado** cuando cumple lo siguiente:

| Criterio | Evidencia mínima |
|---|---|
| Propósito claro | problema, usuarios, contexto y límites definidos |
| Funcionalidad verificable | prueba, demostración, revisión o evidencia de uso |
| Arquitectura documentada | componentes, flujos, dependencias y límites de confianza |
| Seguridad integrada | checklist y gates aplicables documentados |
| Evidencia investigativa | pregunta, instrumento, dato, observación o matriz |
| Experiencia cuidada | accesibilidad, interfaz, narrativa o mediación documentada |
| Documentación viva | README, bitácora, changelog o registro de decisión |
| Transferencia triádica | lectura PH, IT, AT y seguridad |
| Mantenimiento inicial | deuda técnica, próximos pasos o soporte básico |

### 10.1 Señal de N3 falso

Un producto parece N3, pero no lo es, cuando:

```text
funciona en demostración,
pero no tiene arquitectura,
no documenta riesgos,
no tiene evidencia,
no registra decisiones,
no puede mantenerse,
y nadie más puede continuarlo.
```

---

## 11. Rúbrica compacta N4 emergente

Un producto o ecosistema alcanza **N4 emergente** cuando además de N3 avanzado cumple lo siguiente:

| Criterio | Evidencia mínima |
|---|---|
| Escalabilidad | arquitectura reusable o blueprint |
| Despliegue controlado | entorno, configuración, rollback y release documentados |
| Observabilidad | monitoreo, bitácora de operación o protocolo de incidentes |
| DevSecOps inicial | revisión, pruebas, escaneo o CI/CD documentado |
| Gobernanza viva | decisiones, excepciones, responsables y revisión periódica |
| Wiki humana | guías de usuario, FAQ o documentación pública interna |
| Transferencia institucional | adaptación a curso, comunidad, laboratorio o equipo |
| Auditoría | evidencia de evaluación, métricas y mejoras |
| Mantenimiento evolutivo | backlog, deuda técnica, soporte y retiro responsable |

La seguridad longitudinal no debe compensarse totalmente con otras dimensiones.

## 15. Estados de evaluación

| Estado | Significado |
|---|---|
| Exploratorio | Producto temprano, útil para aprendizaje, no estable |
| En desarrollo | Producto con estructura inicial y pendientes claros |
| Apto con observaciones | Puede avanzar con deuda o riesgos documentados |
| Apto para N3 inicial | Cumple integración mínima operativa |
| Apto para N3 avanzado | Integra técnica, evidencia, experiencia, seguridad y documentación |
| N4 emergente | Tiene condiciones iniciales de escalamiento, despliegue y gobernanza |
| Bloqueado | No debe avanzar sin corrección, revisión o decisión explícita |

---

## 16. Indicadores de riesgo evaluativo

| Riesgo | Señal | Acción mínima |
|---|---|---|
| Funcionalidad inflada | Se afirma que funciona sin prueba ni reproducción | pedir evidencia o demostración documentada |
| Seguridad tardía | Se evalúa seguridad solo al final | regresar a G0, G1 y G2 |
| IA opaca | No se sabe cómo se usó IA | exigir bitácora y revisión humana |
| Evidencia débil | No hay datos, pregunta ni instrumento | añadir matriz de evidencia |
| Experiencia pobre | Interfaz, lenguaje o accesibilidad no considerados | activar UN-08 |
| Documentación frágil | Solo hay conversación o memoria informal | crear README, bitácora o changelog |
| Transferencia ficticia | Se declara PH-IT-AT sin equivalencias | usar matriz de transferencia |
| Gobernanza muda | Decisiones importantes no registradas | crear registro de decisión |
| Mantenimiento invisible | No hay ruta de soporte o retiro | crear backlog o runbook mínimo |

## 18. Antipatrones de evaluación

| Antipatrón | Riesgo | Corrección mínima |
|---|---|---|
| Medir solo entrega | Ignora proceso, seguridad y aprendizaje | evaluar dimensiones M-PH-01 a M-PH-11 |
| Medir solo código | Reduce el perfil a programación | incluir evidencia, experiencia, seguridad y transferencia |
| Medir solo intención | Premia declaraciones sin artefactos | exigir evidencia observable |
| Promedio mágico | Oculta riesgo crítico bajo buenas puntuaciones | aplicar regla de seguridad no compensable |
| Checklist vacío | Marca cumplimiento sin evidencia | exigir referencia documental |
| N4 cosmético | Usa palabras avanzadas sin arquitectura ni mantenimiento | exigir despliegue, observabilidad y gobernanza |
| Auditoría tardía | Evalúa cuando ya es costoso corregir | usar gates desde idea y arquitectura |

11. evidencia de que los productos rectores cumplen al menos umbral N3 inicial.

## 20. Locks vigentes

Durante esta fase no se deben crear todavía:

```text
AGENTS.md
CLAUDE.md
SKILLS.md
```
