## 1. Propósito del documento

Este documento define el sistema de **Enlaces Espejo** del Programador Humanista v3.0.0.

Su función es mantener una arquitectura centralizada del perfil sin duplicar documentos técnicos que deben vivir en cartapacios especializados del repositorio.

Los enlaces espejo permiten que el Programador Humanista opere como centro conceptual y operativo, mientras los detalles técnicos, metodológicos, éticos, investigativos, artísticos, de seguridad, despliegue, mantenimiento y documentación humana permanecen en sus cartapacios naturales.

---

## 2. Tesis de enlaces espejo

El Programador Humanista debe mantener una visión central, pero no debe convertirse en un almacén infinito de copias.

```text
Centro conceptual → Perfil Programador Humanista v3.0.0
Detalle especializado → Cartapacios funcionales del Framework V4.1.1
Conexión documentada → Enlaces espejo
Evidencia viva → Documentación activa
```

La regla central es:

```text
Un documento tiene una ubicación oficial.
El perfil puede referenciarlo mediante enlace espejo.
La duplicación solo se permite si se declara como versión adaptada, extracto o síntesis.
```

---

## 3. Definición operativa

Un **enlace espejo** es una referencia documental controlada que conecta un producto central del Programador Humanista con un documento, cartapacio, matriz, checklist, protocolo, guía, registro, evidencia o artefacto ubicado en otro lugar del repositorio.

No es un acceso directo informal. Es una relación documentada con propósito, estado, propietario lógico, ruta y uso esperado.

---

## 4. Principios de enlace espejo

| Principio | Descripción operativa |
|---|---|
| Ubicación oficial única | Cada documento sustantivo debe tener una ruta oficial principal. |
| Centralización conceptual | El perfil conserva la visión, el mapa y la lógica de uso. |
| Especialización documental | Los detalles técnicos viven en cartapacios especializados. |
| Trazabilidad | Cada enlace debe indicar origen, destino, función y estado. |
| No duplicación innecesaria | No se copian documentos completos sin razón explícita. |
| Síntesis permitida | Se pueden crear resúmenes, matrices o extractos si son productos propios del perfil. |
| Actualización responsable | Si cambia el documento fuente, el enlace espejo debe revisarse. |
| Seguridad documental | Los enlaces a seguridad, datos, secretos o riesgos deben manejarse con control. |
| Transferencia triádica | Cada enlace puede tener lectura técnica, investigativa, artística y de confianza. |

---

## 5. Tipos de enlaces espejo

| Tipo | Uso | Ejemplo |
|---|---|---|
| Referencia conceptual | Conecta con fundamentos, principios o arquitectura | Humanismo tecnológico, perfiles transversales |
| Referencia técnica | Conecta con código, repositorios, pruebas, lenguajes o APIs | Git, Laravel, Python, TypeScript, code review |
| Referencia de seguridad | Conecta con privacidad, datos, secretos, OWASP, gates o auditoría | Seguridad de aplicaciones, gestión de secretos |
| Referencia metodológica | Conecta con ciclos, protocolos, fases o SSDLC | Ciclo de vida de proyectos, workflows preliminares |
| Referencia evaluativa | Conecta con métricas, gates, rúbricas o auditorías | Evaluación de seguridad, rúbricas N3/N4 |
| Referencia investigativa | Conecta con evidencia, instrumentos, datos o métodos | Corpus, matriz de evidencia, revisión bibliográfica |
| Referencia artística | Conecta con multimodalidad, visualización, mediación o publicación | Recursos visuales, experiencia, publicación web |
| Referencia educativa | Conecta con cursos, actividades, trayectorias o diseño instruccional | Aplicaciones educativas, evaluación de aprendizaje |
| Referencia de despliegue | Conecta con cloud, contenedores, IaC, CI/CD, runbooks | Docker, Kubernetes, rollback, observabilidad |
| Referencia de mantenimiento | Conecta con deuda técnica, soporte, incidentes o evolución | Backlog, postmortems, planes evolutivos |
| Referencia de documentación humana | Conecta con guías, FAQ, wiki e inicio rápido | Guías de educadores, estudiantes, administradores |
| Referencia histórica | Conecta con versiones cerradas, ciclos completados o archivo | Releases, archivo histórico, exportaciones |


---

## 7. Estados de enlace espejo

| Estado | Significado |
|---|---|
| Activo | El enlace está vigente y puede usarse como referencia. |
| Pendiente | El enlace fue identificado, pero falta validar ruta, contenido o relación. |
| Parcial | El enlace sirve para una parte del producto, pero requiere complemento. |
| En revisión | El enlace debe verificarse por cambio de versión, riesgo o ubicación. |
| Obsoleto | El enlace apunta a contenido superado o desplazado. |
| Archivado | El enlace se conserva por historia, no por uso operativo. |
| Bloqueado | El enlace no debe usarse hasta resolver riesgo, permiso o gobernanza. |

## 22. Riesgos de enlaces espejo

| Riesgo | Descripción | Mitigación |
|---|---|---|
| Duplicación documental | Copiar documentos técnicos dentro del perfil sin necesidad | declarar ruta oficial y usar enlace espejo |
| Enlace huérfano | Referencia sin ruta clara o sin documento fuente | completar plantilla mínima |
| Enlace obsoleto | Ruta o contenido superado por nueva versión | revisar estado y fecha |
| Fragmentación | Información crítica dispersa sin mapa central | mantener este documento actualizado |
| Sobrecentralización | El perfil intenta contener todos los detalles técnicos | mover detalle a cartapacio especializado |
| Seguridad dispersa | Riesgos, gates o secretos no conectados a seguridad | enlazar con `16` y `15` |
| Transferencia falsa | El enlace no aporta lectura PH-IT-AT real | clasificar como parcial o no aplicable |
| Ruta sensible | Enlace revela información que no debe publicarse | registrar advertencia y controlar acceso |
| Archivo perdido | Documento viejo sigue usándose como vigente | mover a `99` o marcar obsoleto |
