## 1. Propósito

Este mapa define cómo consolidar físicamente la Fase 1 revisada del Programador Humanista sin perder historia, referencias ni reversibilidad.

No ejecuta movimientos.

Su función es responder, para cada bloque:

```text
qué permanece
qué se sustituye
qué se conserva como antecedente
qué queda como deuda de residencia
qué se verifica después
```

---

## 2. Regla de consolidación

```text
clasificar
→ identificar fuente canónica
→ registrar deuda
→ incorporar versión aprobada
→ preservar antecedente
→ actualizar referencias
→ verificar árbol e índices
```

No se borra historia para producir apariencia de limpieza.

El cierre operativo requiere solo:

```text

2. declarar reemplazos sin borrar antecedentes;
3. actualizar README del perfil;
4. actualizar Tree / mapa de estructura;
5. actualizar changelog;
6. registrar deuda de `Bases_Conocimiento/`;
7. verificar enlaces principales;
8. generar Resumen Ejecutivo Humano PH.
```

No requiere:

```text

reorganizar toda la macroestructura;
vaciar carpetas históricas;
diseñar Fase 2;
crear agentes o workflows;
ejecutar todavía el prototipo.
```

## 15. Reversibilidad

Toda incorporación debe poder revertirse porque:

- los documentos históricos se preservan;
- no se ejecutan migraciones masivas;
- cada fuente activa tiene antecedente identificable;
- la deuda se registra antes de mover;
- la consolidación separa cambio conceptual de cambio físico.

Regla:

```text
cerrar
!= borrar historia
```
