## 5. Seguridad como especialidad PH

La seguridad técnica forma parte de la especialidad del Programador Humanista.

PH debe comprender y aplicar, cuando corresponda:

```text
Security by Design
Security by Default
SSDLC / SSDF
DevSecOps
OWASP y marcos defensivos
codificación segura
dependencias y secretos
seguridad de APIs y datos
despliegue seguro
rollback y recuperación
observabilidad
seguridad H-M-IA
```

Regla:

```text
seguridad técnica = especialidad PH
```

La existencia de rutas especializadas del Framework permite soporte, evidencia y enlaces, pero no elimina la responsabilidad propia del perfil.

Un riesgo crítico no se compensa con buena funcionalidad.

## 6. CONOCIMIENTO resuelto sin documento artificial

La función CONOCIMIENTO queda resuelta dentro de la gobernanza del perfil.

No se crea un documento canónico independiente denominado "Frontera de Conocimiento".

La regla es simple:

```text
conocimiento específico de construcción tecnológica humanista
→ PH

conocimiento inequívocamente común PH-IT-AT
→ Base Común / macroestructura
```

La carpeta histórica `Bases_Conocimiento/` contiene ambos tipos porque PH fue el perfil piloto.

Eso genera deuda de residencia, no invalida el contenido.

## 10. Control de deriva

Se considera deriva si PH:

- vuelve a reducirse a educación;
- se convierte en desarrollador genérico sin propósito humanista;
- absorbe responsabilidad epistemológica IT;
- absorbe responsabilidad artística AT;
- convierte IA, agentes o herramientas en identidad;
- confunde complejidad técnica con madurez;
- abandona seguridad técnica como especialidad;
- convierte transferencia en obligación triádica;
- acumula conocimiento común como propiedad PH;
- vuelve a usar promedios para compensar riesgos críticos.

La respuesta correcta ante deriva es:

```text
detectar
→ documentar
→ mantener / corregir / reabrir
```

## Robustecimiento empírico aprobado · 2026-09-22

La integración con AI StoryLab 1 no reabre la identidad, las ocho competencias ni las seis Unidades Nucleares del PH.

Introduce cuatro refinamientos de gobernanza.

### 1. Reversibilidad como principio operativo transversal

Una decisión, diseño o transferencia es reversible cuando declara:

```text
estado
+ límites
+ condiciones de salida
+ trazabilidad suficiente
```

de modo que pueda modificarse, retirarse, transferirse o reabrirse sin pérdida material de comprensión o control.

La reversibilidad no crea competencia, Unidad Nuclear ni gate universal adicional.

### 2. Separación de funciones de autoridad

```text
ejecutar
!= verificar
!= interpretar
!= decidir
!= autorizar
!= habilitar
```

La verificación automatizada puede informar una decisión, pero no sustituye autorización humana cuando un gate o cambio estructural la exige.

### 3. Método invocable

SDD queda reconocido como primer caso empírico de método invocable PH.

Un método invocable organiza capacidades existentes y vive canónicamente en la función metodológica del Framework cuando su alcance es reusable.

### 4. Residencia y propiedad

```text
residencia documental != propiedad epistemológica
```

El PH invoca conocimiento común sin apropiárselo y conserva conocimiento específico únicamente cuando depende de su responsabilidad tecnológica propia.
