## 1. Propósito del documento

Este documento define el alcance operativo de la Fase 2 del Programador Humanista v3.0.0 y su relación con la Base de Conocimiento Común PH-IT-AT.

La Fase 2 no se concibe como una simple colección de documentos del Programador Humanista. Se concibe como una infraestructura viva de conocimiento común, específico, transferible, indexable, evaluable y preparada para evolución futura.

El Programador Humanista opera como perfil piloto para estabilizar el patrón documental, metodológico y operativo. Sin embargo, todo conocimiento transversal producido en esta fase debe quedar preparado para ser enriquecido por el Investigador Transdisciplinario y el Artista Transdisciplinario cuando completen sus respectivas Fases 1.

## 2. Principio operativo central

```text
Diseñar para el ecosistema completo.
Producir solo lo necesario en el momento correcto.
Indexar desde el inicio para crecer sin rehacer.
Preservar la simetría entre PH, IT y AT.
Activar el caleidoscopio como propiedad emergente, no como compartimento fijo.
```

La Fase 2 debe ser robusta, resiliente, sostenible y flexible.

| Cualidad | Significado operativo |
|---|---|
| Robusta | Sostiene conocimiento común, específico, reversible, evaluable y seguro. |
| Resiliente | Puede recibir cambios, nuevos perfiles maduros y productos N1-N4 sin romper su arquitectura. |
| Sostenible | Evita proliferación documental innecesaria mediante reglas de creación y ubicación. |
| Flexible | Permite rutas por proyecto, producto, usuario, perfil, nivel y modalidad de trabajo. |

9. sostener seguridad longitudinal desde el inicio;

La Fase 2 no debe implementar todavía todos los sistemas futuros. Debe dejar sus convenciones, índices, metadatos, mapas de expansión y criterios de seguridad preparados.

## 8. Regla para crear documentos nuevos

Antes de crear un documento nuevo, se debe aplicar esta pregunta de control:

```text
¿Esto debe ser un documento independiente, una sección dentro de otro documento o una entrada del índice, glosario, catálogo o registro?
```

Un documento independiente se justifica cuando cumple al menos una de estas condiciones:

```text
1. será invocado con frecuencia;
2. requiere gobernanza propia;
3. afecta seguridad o datos;
4. conecta dos o más perfiles;
5. define una convención transversal;
6. sirve para evaluar progreso N1-N4;
7. será reutilizado por agentes, bases de datos o automatización futura;
8. organiza flujo de conocimiento entre cartapacios;
9. es necesario para trazabilidad institucional;
10. reduce ambigüedad significativa.
```

Si no cumple estas condiciones, debe iniciar como sección, entrada o nota de bitácora.

## 10. Regla de nivel caleidoscópico

En proyectos caleidoscópicos, el nivel operativo principal se define por el perfil activo con menor nivel de madurez.

```text
Nivel operativo del caleidoscopio = menor nivel entre perfiles activos.
```

Ejemplo:

```text
PH = N3
IT = N2
AT = N4

Proyecto triádico = N2
```

Esto protege la transferencia simétrica. El proyecto puede aspirar a N3 o N4, pero debe declarar qué competencias, evidencias o productos faltan para elevar su nivel.

### Hallazgo transferido

La Fase 2 posee solidez suficiente para operar como infraestructura viva de conocimiento. Su valor principal es que combina base común, conocimiento específico, indexación, metadatos, seguridad longitudinal, trazabilidad de proyecto-producto-usuario y transferencia reversible sin convertir el PH en centro jerárquico.

### Impacto en PH

El PH puede avanzar como piloto y producir documentos funcionales, técnicos y educativos, siempre que estos se clasifiquen por metadatos, nivel, seguridad y reusabilidad.
