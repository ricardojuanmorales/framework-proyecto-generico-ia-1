## 1. Propósito del documento

Este documento define la **Matriz de Competencias del Programador Humanista v3.0.0**.

Su función es traducir la fórmula nuclear, el mapa rector, la seguridad longitudinal y la transferencia simétrica triádica en capacidades observables, evaluables y transferibles.

La matriz organiza lo que el Programador Humanista debe saber comprender, diseñar, construir, documentar, evaluar, proteger, mantener y transferir durante su desarrollo desde N1 hasta N4.

---

## 2. Tesis de competencias

El Programador Humanista no se define solo por saber programar. Se define por integrar construcción técnica, pensamiento educativo, evidencia investigativa, experiencia artística, seguridad longitudinal, documentación viva, gobernanza y transferencia.

```text
Competencia PH = capacidad observable + evidencia + contexto humano + seguridad + transferencia
```

Una competencia no queda completa si solo produce acción técnica. Debe dejar rastro, poder evaluarse y poder dialogar con la tríada:

```text
Programador Humanista ↔ Investigador Transdisciplinario ↔ Artista Transdisciplinario
```

---

## 3. Fórmula de competencia operacional

Cada competencia del Programador Humanista se define mediante siete componentes:

| Componente | Pregunta guía |
|---|---|
| Acción | ¿Qué sabe hacer la persona o equipo? |
| Contexto | ¿En qué situación educativa, técnica, investigativa o cultural se aplica? |
| Artefacto | ¿Qué producto, evidencia o transformación genera? |
| Seguridad | ¿Qué riesgos, datos, permisos o controles debe considerar? |
| Documentación | ¿Qué rastro debe dejar? |
| Evaluación | ¿Cómo se sabe que la competencia se logró? |
| Transferencia | ¿Cómo dialoga con investigación, arte, docencia o comunidad? |

## 4. Niveles de desarrollo N1-N4

| Nivel | Descripción general | Tipo de evidencia esperada |
|---|---|---|
| N1 Exploración guiada | Comprende conceptos, sigue instrucciones, modifica plantillas y documenta aprendizajes iniciales | notas, README simple, ejercicios guiados, reflexión breve |
| N2 Producción asistida | Construye productos simples con apoyo de IA, plantillas y revisión humana | prototipo básico, script simple, matriz inicial, bitácora de proceso |
| N3 Integración operativa | Integra diseño, código, IA, datos, documentación, evaluación, seguridad y transferencia en flujos reproducibles | aplicación funcional, repositorio, checklist, pruebas, matriz de transferencia, evidencia de revisión |
| N4 Ecosistema autosostenido | Diseña arquitecturas escalables, auditables, mantenibles y transferibles a equipos, cursos o instituciones | arquitectura completa, gates, CI/CD, despliegue, observabilidad, documentación humana, auditoría y transferencia avanzada |

## 7. Competencias detalladas

### PH-C01 Identidad, ética y humanismo tecnológico

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Explica el propósito humanista del perfil y reconoce límites básicos del uso de tecnología | reflexión breve o nota de propósito |
| N2 | Aplica criterios éticos iniciales a un prototipo o actividad | ficha de propósito, usuarios y límites |
| N3 | Documenta decisiones éticas, riesgos, accesibilidad, privacidad y revisión humana | registro de decisión o matriz de riesgos |
| N4 | Diseña prácticas de gobernanza ética para equipos, cursos o ecosistemas | política, rúbrica o protocolo institucional |

### PH-C02 Pensamiento computacional y arquitectura

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Descompone un problema en pasos, actores y entradas básicas | mapa simple de flujo |
| N2 | Modela un proceso con componentes, datos y salidas | diagrama, pseudocódigo o tabla de componentes |
| N3 | Diseña arquitectura modular con límites, dependencias, riesgos y enlaces espejo | mapa de arquitectura y decisiones |
| N4 | Diseña arquitectura escalable, reusable, segura y mantenible | arquitectura de referencia, runbook o blueprint |

### PH-C03 Desarrollo técnico y producción de artefactos

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Ejecuta o modifica código guiado sin romper su función básica | ejercicio documentado |
| N2 | Construye prototipo funcional simple con apoyo de IA o plantilla | prototipo, script o repositorio básico |
| N3 | Integra código, datos, APIs, pruebas, control de versiones y documentación | aplicación funcional con README, pruebas y checklist |
| N4 | Diseña sistemas desplegables, observables, mantenibles y transferibles | sistema con CI/CD, despliegue, monitoreo y guías |

### PH-C04 IA aplicada y colaboración humano-máquina

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Usa IA para explorar ideas, resumir o generar borradores con revisión humana | prompt y reflexión breve |
| N2 | Usa IA para asistir código, documentación, diseño o evaluación | bitácora de uso y revisión |
| N3 | Integra IA en un flujo reproducible con límites, datos y criterios de validación | flujo documentado, decisiones y revisión humana |
| N4 | Diseña ecosistemas humano-IA con roles, memoria, seguridad, evaluación y gobernanza | arquitectura humano-IA y protocolo operativo |

### PH-C05 Diseño educativo y experiencia de aprendizaje

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Identifica objetivo de aprendizaje, público y contexto | ficha de actividad |
| N2 | Diseña recurso, actividad o evaluación asistida por tecnología | actividad o rúbrica inicial |
| N3 | Construye aplicación o flujo educativo evaluable y accesible | prototipo educativo con criterios de evaluación |
| N4 | Diseña trayectoria educativa completa con IA, evidencia, accesibilidad y transferencia | mapa curricular, programa o ecosistema formativo |

### PH-C06 Investigación, evidencia y trazabilidad

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Reconoce fuentes, datos, observaciones y preguntas investigables | lista de fuentes o pregunta inicial |
| N2 | Crea instrumento simple, matriz o registro de evidencia | matriz, encuesta, rúbrica o bitácora |
| N3 | Conecta artefacto con datos, corpus, método, validez y trazabilidad | protocolo, matriz de evidencia o reporte |
| N4 | Diseña línea investigativa o producto publicable basado en artefactos | paper, informe, dataset o síntesis avanzada |

### PH-C07 Arte, mediación y experiencia significativa

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Reconoce elementos de experiencia, lenguaje, interfaz y accesibilidad | análisis breve de experiencia |
| N2 | Diseña narrativa, interfaz, visualización o mediación simple | storyboard, wireframe, guion o mockup |
| N3 | Integra experiencia artística, accesibilidad y sentido en un artefacto funcional | prototipo multimodal o interfaz documentada |
| N4 | Diseña experiencias públicas, transmedia o culturalmente situadas | instalación, presentación, portal o mediación avanzada |

### PH-C08 Seguridad, privacidad y confianza longitudinal

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Reconoce datos, permisos, riesgos básicos y límites de uso | ficha de riesgos básica |
| N2 | Aplica checklist inicial de seguridad, privacidad y configuración | checklist completado |
| N3 | Integra gates, codificación segura, revisión de dependencias, secretos y despliegue seguro | evidencia de gates G0-G7, revisión o bitácora |
| N4 | Diseña prácticas de SSDLC, DevSecOps, monitoreo, incidentes y mejora continua | pipeline, runbook, auditoría o protocolo de seguridad |

### PH-C09 Documentación viva, gobernanza y repositorios

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Crea README, notas o estructura documental simple | README o nota de sesión |
| N2 | Mantiene bitácora, changelog, decisiones y versiones básicas | changelog, registro o commit documentado |
| N3 | Documenta arquitectura, transferencia, seguridad, pruebas, decisiones y enlaces espejo | paquete documental coherente |
| N4 | Administra documentación viva multiusuario, auditable y transferible | wiki, gobernanza, archivo histórico y protocolo de continuidad |

### PH-C10 Mantenimiento, despliegue, transferencia y evolución

| Nivel | Desempeño observable | Evidencia mínima |
|---|---|---|
| N1 | Reconoce límites, pendientes y próximos pasos | lista de pendientes |
| N2 | Define soporte básico, deuda técnica y versión siguiente | backlog inicial |
| N3 | Mantiene versiones, despliegue, incidentes, guías humanas y transferencia | release, runbook, guía o postmortem |
| N4 | Escala artefactos a cursos, comunidades, equipos o instituciones | plan de evolución, transferencia o escalamiento |

## 13. Antipatrones competenciales

| Antipatrón | Descripción | Corrección mínima |
|---|---|---|
| Solo código | La competencia se mide solo por producir código | añadir propósito, documentación, seguridad y transferencia |
| Solo teoría | La competencia no produce artefactos verificables | añadir prototipo o evidencia práctica |
| IA sin revisión | La IA produce salidas sin evaluación humana | registrar uso, límites y revisión |
| Seguridad tardía | Los riesgos se revisan al final | aplicar gates desde idea, requisitos y arquitectura |
| Arte decorativo | La experiencia se añade como adorno | integrar mediación desde diseño |
| Investigación desconectada | No hay evidencia ni método | conectar artefacto con preguntas e instrumentos |
| Documentación fantasma | El proceso queda en conversación informal | crear README, bitácora o registro de decisión |
| Transferencia fingida | Se afirma simetría sin evidencia | clasificar como parcial o pendiente |
