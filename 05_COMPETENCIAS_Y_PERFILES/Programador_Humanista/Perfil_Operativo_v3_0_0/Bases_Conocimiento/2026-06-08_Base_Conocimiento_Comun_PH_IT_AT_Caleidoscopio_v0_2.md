## 0. Propósito

Esta Base de Conocimiento Común establece el fundamento vivo, trazable y reusable para el ecosistema PH-IT-AT-Caleidoscopio del Framework Genérico V4.1.1.

Su propósito es servir como raíz compartida para:

```text
formación N1-N4;
especialización futura de PH, IT y AT;
interacción humano-máquina-IA;
uso ético y responsable de IA;
pensamiento sistémico, holístico y transdisciplinario;
documentación y trazabilidad;
seguridad longitudinal;
documentos invocables como artefactos funcionales;
activación caleidoscópica latente.
```

Este documento no cancela el paquete mínimo anterior. Lo preserva como semilla histórica y lo supera mediante una arquitectura común más profunda.

## 1. Definición central

La Base de Conocimiento Común PH-IT-AT-Caleidoscopio es una **arquitectura de referencia viva** que reúne fundamentos, competencias, buenas prácticas, criterios éticos, estructuras de seguridad, documentos invocables y reglas de transferencia para sostener la evolución de los perfiles especializados.

```text
No es una carpeta.
No es solo un manual.
No es una lista de prompts.
No es un currículo cerrado.
Es una raíz viva de orientación, formación, producción, evaluación y transferencia.
```

---

## 2. Principios rectores

### 2.1 Agencia humana preservada

La IA asiste, expande, organiza y acelera, pero no sustituye la responsabilidad humana. Toda decisión relevante requiere revisión humana proporcional al riesgo.

### 2.2 Tecnología como mediación

La tecnología se entiende como mediación entre intención, conocimiento, práctica, comunidad y producto. No es neutral ni mágica. Debe contextualizarse.

### 2.3 Conocimiento situado y trazable

Todo conocimiento nace en un contexto, responde a un propósito y deja rastros. La trazabilidad protege memoria, calidad, revisión y aprendizaje.

### 2.4 Complejidad sin caos

El ecosistema acepta complejidad, pero la gobierna mediante módulos, niveles, rutas, metadatos, revisión humana y regla semáforo.

### 2.5 Transferencia simétrica reversible

El conocimiento común alimenta a PH, IT y AT. Los perfiles devuelven prácticas, evidencias y mediaciones que actualizan la base común.

### 2.6 Seguridad longitudinal

La seguridad acompaña todo el ciclo de vida. No se añade al final como barniz de último minuto.

### 2.7 Suficiencia mínima y expansión responsable

Se crea lo necesario para avanzar con claridad. La expansión se registra, se justifica y se revisa.

## 3. Capas de lectura N1-N4

Cada módulo se puede leer en tres capas vinculadas a los niveles N1-N4.

| Capa | Función | Niveles dominantes |
|---|---|---|
| Uso humano cotidiano | Permite comprender y usar sin sobrecarga. | N1/N2 |
| Formación universitaria | Desarrolla conceptos, competencias y prácticas. | N2/N3 |
| Marco epistemológico profundo | Examina fundamentos, límites, tensiones y posibilidades. | N3/N4 |

Los niveles no segregan usuarios rígidamente. Funcionan como andamiaje progresivo. Un usuario N1 puede comenzar con apoyo, mientras un usuario N4 puede auditar, expandir y gobernar.

## 5. Fundamento filosófico común

La base común parte de una visión de conocimiento como práctica humana situada, mediada por herramientas, orientada por valores y expuesta a consecuencias.

### 5.1 Supuestos de partida

```text
El conocimiento no aparece aislado: se produce en contextos.
La IA no reemplaza el juicio humano: lo desafía y lo amplifica.
La documentación no es burocracia: es memoria operativa y ética.
La creatividad requiere estructura para transferirse.
La investigación requiere trazabilidad para sostener confianza.
La técnica requiere sentido para no convertirse en automatismo.
La complejidad requiere gobernanza para no volverse ruido.
```

### 5.2 Valores operativos

| Valor | Implicación |
|---|---|
| Responsabilidad | Toda pieza debe tener propósito, límites y revisión. |
| Claridad | Lo complejo debe organizarse para ser usado. |
| Cuidado | Las personas, datos, contextos y comunidades importan. |
| Trazabilidad | Las decisiones deben poder reconstruirse. |
| Apertura crítica | El sistema aprende, pero no acepta cualquier expansión sin criterio. |
| Pluralidad | Los perfiles y saberes dialogan sin anularse. |
| Sostenibilidad | La base debe poder mantenerse, no solo crecer. |

### 5.3 Preguntas filosóficas guía

```text
¿Qué tipo de ser humano y comunidad formamos al usar IA?
¿Qué delegamos y qué no debemos delegar?
¿Qué evidencia necesitamos para confiar en un producto?
¿Qué queda invisible cuando automatizamos?
¿Qué voces, saberes o experiencias quedan fuera?
¿Cómo mantenemos sentido, responsabilidad y belleza en sistemas técnicos?
```

## 9. Ética e IA responsable

El uso de IA en la base común debe ser deliberado, revisable y proporcional al riesgo.

### 9.1 Reglas mínimas

```text
No compartir datos sensibles sin necesidad, autorización y protección.
No publicar resultados sin revisión humana.
No presentar respuestas generadas como verdad final.
No usar IA para ocultar falta de evidencia.
No automatizar decisiones de alto impacto sin gobernanza explícita.
No borrar la autoría, responsabilidad o participación humana.
No confundir fluidez textual con validez.
```

### 9.2 Buenas prácticas

```text
declarar el uso de IA cuando corresponda;
verificar datos cambiantes;
distinguir hechos, inferencias y propuestas;
usar fuentes confiables;
registrar decisiones;
conservar versiones relevantes;
evaluar sesgos;
revisar tono, accesibilidad y pertinencia;
limitar alcance cuando falte evidencia.
```

### 9.3 Preguntas éticas mínimas

```text
¿Qué riesgo tiene esta tarea?
¿Quién podría verse afectado?
¿Qué datos se usan?
¿Qué decisión humana permanece activa?
¿Qué se debe verificar?
¿Qué transparencia se requiere?
¿Qué límites deben declararse?
```

## 10. Competencias humano-máquina-IA

La interacción humano-máquina-IA requiere competencias prácticas y críticas.

### 10.1 Ciclo mínimo de interacción

```text
1. Activar contexto.
2. Definir objetivo.
3. Delimitar alcance.
4. Proveer materiales necesarios.
5. Solicitar salida concreta.
6. Revisar críticamente.
7. Iterar con criterio.
8. Documentar decisión.
9. Registrar deuda.
10. Cerrar con continuidad.
```

### 10.2 Competencias observables

| Competencia | Señal observable |
|---|---|
| Contextualizar | El usuario sitúa la tarea dentro del proyecto. |
| Preguntar | La solicitud tiene propósito, límites y salida esperada. |
| Revisar | El usuario no acepta la respuesta sin juicio crítico. |
| Verificar | Se contrastan datos, fuentes o supuestos cuando aplique. |
| Documentar | Se registran decisiones, rutas y deuda. |
| Transferir | Se conecta lo producido con PH, IT, AT o Caleidoscopio. |
| Cuidar | Se atienden privacidad, accesibilidad y efectos humanos. |

## 12. Seguridad longitudinal

La seguridad longitudinal opera durante todo el ciclo de vida del conocimiento.

| Momento | Riesgo | Acción mínima |
|---|---|---|
| Creación | Incluir datos sensibles o supuestos no revisados | Usar datos simulados, anonimizar, declarar límites. |
| Clasificación | Mezclar común y específico | Etiquetar tipo de conocimiento. |
| Uso | Aplicar fuera de contexto | Incluir cuándo usar y cuándo no usar. |
| Invocación | Delegar demasiado a IA | Exigir revisión humana. |
| Transferencia | Borrar origen o autoría | Mantener trazabilidad. |
| Publicación | Difundir errores | Verificar, revisar y declarar uso de IA. |
| Expansión | Inflación documental | Aplicar regla semáforo. |
| Automatización futura | Activar agentes sin gobernanza | Bloquear hasta autorización explícita. |

## 16. Activación caleidoscópica latente

La activación caleidoscópica ocurre cuando múltiples módulos y perfiles se recombinan para producir una lectura o producto nuevo.

### 16.1 Estado actual

```text
Latente.
No autónomo.
No agente.
No automatizado.
Preparado para recombinación humana guiada.
```

### 16.2 Criterios para activar lectura caleidoscópica

```text
hay conocimiento común suficiente;
hay al menos dos perfiles implicados;
hay pregunta compleja;
hay necesidad de integrar técnica, método y experiencia;
hay revisión humana;
hay seguridad longitudinal aplicada.
```

## 17. Gobernanza de complejidad emergente

La base común usa regla semáforo.

```text
Verde: integrar al módulo actual.
Amarillo: registrar como deuda o expansión futura.
Rojo: crear documento nuevo solo si hay función clara, ruta, uso y revisión.
```

### 17.1 Criterios para crear documento nuevo

```text
no cabe razonablemente en módulo existente;
tiene usuario o uso identificable;
requiere ruta canónica;
genera valor operativo, formativo o evaluativo;
necesita trazabilidad propia;
puede mantenerse sin crear caos.
```

## 20. Uso recomendado por nivel

### N1

Usar guías humanas, checklists, ejemplos, mapas simples y bitácoras guiadas.

### N2

Usar plantillas, protocolos básicos, rúbricas simples y ejercicios de transferencia.

### N3

Diseñar invocables, integrar módulos, aplicar seguridad longitudinal y producir artefactos funcionales.

### N4

Auditar la base, crear marcos de gobernanza, preparar publicaciones, diseñar evaluación avanzada y decidir expansión.

---

## 21. Uso recomendado por perfil

### PH

Usa la base común para diseñar herramientas, repositorios, prototipos, documentación operativa, procesos técnicos y productos tangibles con sentido humano.

### IT

Usa la base común para diseñar investigación, curar conocimiento, producir evidencia, preparar publicaciones, evaluar metodologías y sostener integridad académica.

### AT

Usa la base común para diseñar mediaciones, experiencias, narrativas, visualizaciones, materiales accesibles y traducciones sensibles del conocimiento.

### Caleidoscopio

Usa la base común como sustrato de recombinación cuando una pregunta requiere múltiples perfiles, niveles y lentes.
