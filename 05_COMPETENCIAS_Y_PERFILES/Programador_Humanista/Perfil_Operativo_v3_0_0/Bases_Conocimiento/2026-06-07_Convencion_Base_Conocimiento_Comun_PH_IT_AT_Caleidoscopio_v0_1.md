## 0. Propósito

Esta convención fija la definición estratégica de la **Base de Conocimiento Común PH-IT-AT-Caleidoscopio** para la Fase 2 Ronda 2A del Framework Genérico V4.1.1.

La base común no se define como un simple repositorio de documentos, ni como una carpeta de apoyo, ni como un currículo lineal cerrado. Se define como una **arquitectura de referencia viva** que sostiene la formación, producción, evaluación, transferencia y evolución de los perfiles PH, IT y AT, manteniendo al Caleidoscopio como propiedad emergente.

Esta convención existe para evitar tres riesgos:

```text
1. Reducir el conocimiento común a infraestructura documental.
2. Especializar PH, IT y AT antes de construir una raíz compartida.
3. Producir documentos invocables sin fundamento filosófico, ético y sistémico.
```

---

## 1. Decisión estratégica de Ronda 2A

```text
Fase 2 Ronda 2A se dedica a profundizar la Base de Conocimiento Común PH-IT-AT-Caleidoscopio antes de continuar con la Base Específica PH.
```

Esta decisión preserva el paquete mínimo v0.1 como **semilla histórica** y crea una arquitectura superior para desarrollar la base común robusta.

---

## 2. Definición operativa de conocimiento común

La **Base de Conocimiento Común PH-IT-AT-Caleidoscopio** es el conjunto vivo, trazable y revisable de fundamentos, competencias, principios, buenas prácticas, metodologías transversales, criterios éticos, estructuras de seguridad, guías humanas y documentos invocables que sostienen a todos los perfiles del ecosistema.

Su función no es homogeneizar los perfiles, sino darles un suelo compartido para que puedan diferenciarse sin fragmentarse.

```text
Conocimiento común = raíz compartida.
PH, IT y AT = especializaciones vivas.
Caleidoscopio = propiedad emergente de recombinación sistémica.
```

---

## 3. Naturaleza de la base común

La base común debe operar simultáneamente como:

| Naturaleza | Función |
|---|---|
| Arquitectura de referencia viva | Organiza módulos, relaciones, criterios y rutas de expansión. |
| Tronco formativo N1-N4 | Permite aprendizaje progresivo para usuarios, productos y procesos. |
| Fundamento filosófico compartido | Contextualiza las prácticas técnicas, investigativas y creativas. |
| Sistema de transferencia simétrica | Permite circulación reversible entre conocimiento común, PH, IT y AT. |
| Membrana de seguridad longitudinal | Acompaña la creación, uso, expansión y posible automatización futura. |
| Biblioteca de artefactos funcionales | Incluye documentos invocables trazables, revisables y expandibles. |
| Semillero caleidoscópico | Permite recombinaciones futuras sin activar agentes prematuros. |

---

## 4. Principio de arquitectura de referencia viva

La base común no debe cerrarse como manual único. Debe funcionar como una arquitectura modular que pueda:

```text
crecer;
ser revisada;
recibir evidencia;
producir guías;
generar artefactos funcionales;
transferirse hacia perfiles especializados;
recibir retroalimentación desde esos perfiles;
prepararse para estructuras futuras sin automatización prematura.
```

La arquitectura vive porque el conocimiento se usa, se revisa y regresa transformado.

---

## 5. Principio de tronco formativo N1-N4

La base común sostiene una progresión N1-N4 para personas, procesos, productos y documentos.

| Nivel | Sentido formativo | Sentido operativo |
|---|---|---|
| N1 | Alfabetización, comprensión básica y uso guiado | Seguir guías, reconocer límites, documentar con apoyo. |
| N2 | Aplicación contextual y práctica responsable | Adaptar plantillas, producir evidencias, revisar calidad básica. |
| N3 | Integración sistémica y producción autónoma supervisada | Diseñar módulos, evaluar riesgos, transferir entre perfiles. |
| N4 | Gobernanza, investigación, expansión y sostenibilidad | Auditar, publicar, diseñar arquitecturas, preparar automatización gobernada. |

El proyecto se encuentra trabajando actualmente en un nivel **N3/N4 operativo**, pero la base debe permitir que usuarios N1 y N2 puedan entrar con andamiaje apropiado.

---

## 6. Tres capas de lectura

Cada módulo importante de la base común debe poder leerse en tres capas.

| Capa | Descripción | Relación con niveles |
|---|---|---|
| Capa 1 - Uso humano cotidiano | Explica para qué sirve y cómo usarlo sin sobrecarga conceptual. | N1/N2 |
| Capa 2 - Formación universitaria | Desarrolla conceptos, competencias, criterios y actividades. | N2/N3 |
| Capa 3 - Marco epistemológico profundo | Explicita fundamentos, supuestos, tensiones, límites y posibilidades investigativas. | N3/N4 |

Estas capas no son documentos separados por defecto. Son perspectivas de lectura que deben estar disponibles cuando el módulo lo requiera.

---

## 7. Transferencia simétrica reversible

La base común mantiene transferencia activa entre conocimiento común, PH, IT y AT.

```text
Conocimiento común ↔ PH ↔ IT ↔ AT ↔ Caleidoscopio
```

La transferencia es simétrica porque ningún perfil queda como centro jerárquico permanente. Es reversible porque los aprendizajes pueden circular en ambas direcciones.

| Movimiento | Función |
|---|---|
| Común → PH | Traduce fundamentos en estructura, documentación, implementación y productos. |
| Común → IT | Traduce fundamentos en metodología, evidencia, análisis y publicación. |
| Común → AT | Traduce fundamentos en mediación, experiencia, accesibilidad y expresión. |
| PH → Común | Devuelve prácticas operativas, patrones técnicos y lecciones de implementación. |
| IT → Común | Devuelve marcos conceptuales, evidencias, criterios y curaduría. |
| AT → Común | Devuelve lecturas humanas, mediaciones, visualizaciones y sensibilidad contextual. |
| Perfiles ↔ Perfiles | Permite co-desarrollo sin borrar identidad especializada. |
| Perfiles ↔ Caleidoscopio | Permite recombinación sistémica, holística y transdisciplinaria. |

## 10. Documento invocable como artefacto funcional

Un documento invocable no es solamente un prompt. Es un **artefacto funcional** que permite activar una tarea humana, técnica, investigativa, creativa o evaluativa con propósito, límites y trazabilidad.

Debe contener:

```text
fundamento;
propósito;
contexto de uso;
nivel N1-N4;
entradas requeridas;
procedimiento;
salida esperada;
criterios de calidad;
criterios de seguridad;
criterios de revisión humana;
relación con PH, IT y AT;
posible activación caleidoscópica;
trazabilidad;
deuda generada;
compatibilidad futura.
```

El artefacto funcional debe ser legible por humanos y compatible con futura estructuración técnica, sin activar agentes ni automatizaciones sin gobernanza explícita.

## 11. Regla semáforo para complejidad emergente

Para evitar inflación documental y pérdida de coherencia, toda complejidad nueva se clasifica con una regla semáforo:

| Color | Decisión | Criterio |
|---|---|---|
| Verde | Integrar al módulo actual | Es necesario para comprender o usar el módulo. |
| Amarillo | Registrar como deuda o expansión futura | Es valioso, pero no necesario ahora. |
| Rojo | Crear documento nuevo solo si tiene función clara | Requiere ruta, propósito, uso y relación con la arquitectura. |

La regla semáforo no bloquea la creatividad. La canaliza.

¿Qué deuda deja visible?
¿Cómo se expande sin perder coherencia?

## 14. Compatibilidad futura

La base común debe ser Markdown-first y JSON-compatible.

```text
Markdown = lectura humana, revisión, edición, portabilidad.
JSON = estructuración futura, tableros, inventarios, interoperabilidad.
Bases de datos = posible fase avanzada.
Agentes gobernados = posibilidad futura, no activación presente.
```

No se deben activar agentes, multiagentes, CI/CD, AGENTS.md o SKILLS.md sin gobernanza explícita.
