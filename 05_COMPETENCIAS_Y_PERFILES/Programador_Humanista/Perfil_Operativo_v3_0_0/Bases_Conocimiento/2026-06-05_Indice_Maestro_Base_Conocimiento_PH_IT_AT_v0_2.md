## 0. Propósito del documento

Este Índice Maestro organiza la Base de Conocimiento PH-IT-AT para la Fase 2 del Programador Humanista v3.0.0 y su transferencia futura hacia el Investigador Transdisciplinario y el Artista Transdisciplinario.

Su función no es listar archivos de forma pasiva. Su función es servir como mapa vivo para:

```text
1. ubicar conocimiento común;
2. ubicar conocimiento específico por perfil;
3. identificar documentos invocables;
4. sostener trazabilidad N1-N4;
5. preparar compatibilidad futura con JSON y bases de datos;
6. orientar la producción gradual de documentos;
7. evitar duplicación documental;
8. proteger la simetría PH-IT-AT;
9. habilitar invocación caleidoscópica dinámica;
10. mantener seguridad, privacidad, revisión humana y gobernanza;
11. registrar referencias lógicas sin crear copias físicas;
12. evitar deuda invisible durante la sesión.
```

El índice debe actualizarse cada vez que se cree, mueva, consolide, archive, depreque o reubique un documento importante de Fase 2.

## 2. Principio de navegación

```text
El conocimiento se organiza jerárquicamente,
se conecta reversiblemente,
se invoca dinámicamente,
se evalúa por proyecto, producto y usuario,
y se referencia lógicamente sin duplicar archivos canónicos.
```

La jerarquía no debe convertirse en rigidez. El caleidoscopio emerge cuando el conocimiento común, los perfiles PH-IT-AT, los niveles N1-N4, las etiquetas de reusabilidad y los problemas concretos se combinan de forma trazable.

## 6. Criterio para crear documentos nuevos

Antes de crear un documento nuevo, debe aplicarse la siguiente pregunta de control:

```text
¿Esto debe ser un documento independiente,
una sección dentro de otro documento,
una entrada del glosario,
un registro en catálogo,
una nota de bitácora reversible,
o una entrada de referencia lógica?
```

### 6.1 Crear documento independiente cuando

```text
1. tiene propósito rector o normativo;
2. será invocado con frecuencia;
3. organiza múltiples documentos;
4. requiere control de versión propio;
5. afecta seguridad, gobernanza, metadatos o transferencia;
6. será usado por varios perfiles o niveles;
7. prepara una transición futura relevante.
```

### 6.2 Crear sección dentro de otro documento cuando

```text
1. el contenido no requiere versión independiente;
2. solo explica una parte del documento actual;
3. no tiene uso autónomo;
4. no necesita ser invocado por separado.
```

### 6.3 Crear entrada de glosario cuando

```text
1. el asunto es principalmente conceptual o terminológico;
2. requiere definición común;
3. tiene usos distintos en PH, IT y AT;
4. puede generar ambigüedad;
5. necesita ejemplos o riesgos de mal uso.
```

### 6.4 Crear registro de catálogo cuando

```text
1. se trata de un documento, herramienta, metodología o proceso ya existente;
2. solo se necesita ubicar, clasificar o enlazar;
3. no requiere desarrollo conceptual extenso.
```

### 6.5 Crear nota de bitácora reversible cuando

```text
1. se documenta una decisión, hallazgo o transferencia puntual;
2. existe impacto entre perfiles;
3. se debe preservar trazabilidad sin crear un documento rector.
```

### 6.6 Crear entrada de referencia lógica cuando

```text
1. un documento canónico debe ser invocado desde otro lugar;
2. no se debe crear copia física;
3. se necesita conectar índice, bitácora, registro o perfil;
4. se requiere evitar deuda invisible;
5. se debe mantener fuente única de verdad.
```

## 8. Etiquetas de reusabilidad transversal

Cada documento, entrada, metodología, herramienta, rúbrica o producto debe usar una o más etiquetas de reusabilidad.

| Etiqueta | Significado |
|---|---|
| `comun` | Aplica a PH, IT y AT |
| `PH` | Específico del Programador Humanista |
| `IT` | Específico del Investigador Transdisciplinario |
| `AT` | Específico del Artista Transdisciplinario |
| `PH-IT` | Reutilizable en combinación PH e IT |
| `PH-AT` | Reutilizable en combinación PH y AT |
| `IT-AT` | Reutilizable en combinación IT y AT |
| `triadico` | Requiere o favorece los tres perfiles |
| `caleidoscopico` | Puede invocarse dinámicamente según problema común |
| `seguridad` | Relacionado con seguridad longitudinal |
| `metadatos` | Relacionado con indexación, JSON o base de datos futura |
| `documentacion_humana` | Diseñado para comprensión, uso y acompañamiento humano |
| `automatizacion_futura` | Prepara automatización, pero no la activa |
| `agentes_futuros` | Prepara agentes o multiagentes, pero no los activa |
| `evaluacion` | Relacionado con rúbricas, evidencias o medición |
| `transferencia_reversible` | Debe alimentar bitácora, notas reversas o vínculos entre perfiles |
| `referencia_logica` | No duplica documento; apunta a una fuente canónica |

| N1 | Todo el ciclo visto de forma guiada | Ejemplos, prompts básicos, checklist simple | Ficha, guía breve, bitácora inicial | Producto mínimo, reflexión, checklist | Acceso a base común |
| N2 | Todo el ciclo con producción asistida | Plantillas, flujos, documentación básica | Protocolo básico, plantilla, prompt mejorado | Producto funcional, trazabilidad inicial | N1 + producción asistida |
| N3 | Todo el ciclo con integración avanzada | Matrices, evaluación, automatización parcial | Producto compuesto, rúbrica, tablero inicial | Evaluación, evidencias, transferencia | N1-N2 + integración |
| N4 | Todo el ciclo con gobernanza robusta | Agentes futuros, CI/CD, pruebas, seguridad avanzada | Ecosistema, workflow gobernado, sistema sostenible | Auditoría, pruebas, operación documentada | N1-N3 + gobernanza |

### 12.1 Regla de acumulación

```text
Cada nivel conserva las competencias del nivel anterior.
Cada nivel añade nuevas destrezas, responsabilidades, evidencias y criterios de seguridad.
```

---

## 13. Regla de nivel caleidoscópico

En proyectos caleidoscópicos, el nivel operativo aplicable se determina por el perfil activo con menor nivel.

```text
Nivel operativo del caleidoscopio = menor nivel entre perfiles activos.
```

Ejemplo:

```text
PH = N3
IT = N2
AT = N4

Proyecto triádico operativo = N2
```

Esto protege la transferencia simétrica. El sistema puede mostrar el mapa para llegar a N3 o N4, pero no debe declarar el proyecto como N3 o N4 si uno de los perfiles activos no sostiene ese nivel.

**Estado de transferencia:** Reversible activa.  

### Hallazgo transferido

La Base de Conocimiento PH-IT-AT requiere un índice maestro vivo, pero el índice debe respetar estrictamente el mapa estructural auditado. La versión v0.2 corrige rutas no canónicas, incorpora el protocolo de convenciones v0.3 y establece la referencia lógica como alternativa estándar a los espejos físicos.

### Impacto en PH

El PH conserva la función de perfil piloto, pero sus documentos de Fase 2 deben colocarse en carpetas semánticas existentes: `Alcance_Operativo/`, `Bases_Conocimiento/`, `Enlaces_Espejo/`, `Gobernanza_Perfil/`, `Transferencia_Simetrica/`, `Metricas/`, `Competencias/` u otras rutas auditadas según corresponda.

### Impacto en IT

El IT podrá incorporar sus aportes futuros usando las mismas familias documentales, metadatos, taxonomía, niveles y referencias lógicas, sin depender de una arquitectura centrada exclusivamente en PH.

### Impacto en AT

El AT podrá incorporar mediaciones, narrativas, interfaces, experiencias y criterios sensibles usando el mismo sistema de indexación y transferencia reversible.

### Impacto en Caleidoscopio

El caleidoscopio queda preparado como propiedad emergente de combinaciones dinámicas, no como compartimento fijo. Sus activaciones dependerán de problema común, etiquetas, niveles, perfiles activos, lente latente, curaduría transdisciplinaria y seguridad longitudinal.
