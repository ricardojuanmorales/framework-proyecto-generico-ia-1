## 0. Propósito

Este catálogo organiza herramientas y procesos básicos para operar la Fase 2 PH-IT-AT de forma sistémica, holística y transdisciplinaria.

Su propósito no es recomendar herramientas por moda. Su propósito es ubicar cada herramienta dentro de un sistema de trabajo con:

```text
1. propósito claro;
2. nivel N1-N4;
3. perfil principal;
4. evidencia esperada;
5. riesgos;
6. seguridad;
7. documentación;
8. transferencia reversible;
9. preparación futura para automatización;
10. invocación caleidoscópica.
```

---

## 1. Principio rector

```text
Una herramienta no sustituye el método.
Un proceso no sustituye la reflexión.
La automatización no sustituye la revisión humana.
La documentación convierte el uso de herramientas en conocimiento transferible.
```

## 5. Procesos básicos de Fase 2

### 5.1 Proceso de creación documental

```text
necesidad
→ clasificar tipo de documento
→ consultar protocolo de carpetas
→ definir ruta canónica
→ aplicar plantilla MD/JSON
→ asignar metadatos
→ registrar deuda de referencias
→ producir documento
→ registrar en catálogo o índice si aplica
→ anotar en bitácora
→ preparar cierre o próxima acción
```

### 5.2 Proceso de colocación documental

```text
documento creado
→ validar ruta existente
→ colocar archivo canónico
→ evitar copia física editable
→ registrar referencia lógica
→ actualizar registro de cartapacios
→ actualizar índice si corresponde
→ anotar deuda o cierre
```

### 5.3 Proceso de actualización de glosario

```text
término propuesto
→ verificar duplicados
→ aplicar plantilla de entrada
→ clasificar por taxonomía
→ revisar seguridad y riesgo de mal uso
→ incluir en lote
→ actualizar glosario al cierre de lote
→ registrar deuda y referencias
```

### 5.4 Proceso de transferencia reversible

```text
producto o hallazgo
→ identificar perfil origen
→ identificar perfiles destino
→ registrar impacto PH, IT, AT
→ decidir si va a base común o específica
→ crear referencia lógica
→ actualizar bitácora de transferencia
→ evaluar invocación caleidoscópica
```

### 5.5 Proceso de cierre de bloque

```text
revisar canvas activo de deuda
→ pagar deudas críticas
→ exportar registro si aplica
→ actualizar índice maestro
→ actualizar bitácora
→ actualizar changelog
→ verificar rutas canónicas
→ preparar próxima acción
```

### 5.6 Proceso de seguridad mínima

```text
identificar datos o riesgos
→ clasificar seguridad
→ revisar privacidad
→ revisar IA o automatización
→ exigir revisión humana si aplica
→ registrar bloqueo o condición
→ documentar decisión
```

## 9. Estados de herramientas y procesos

| Estado | Significado |
|---|---|
| `activo` | Puede usarse en Fase 2. |
| `recomendado` | Se sugiere su uso con andamiaje. |
| `en_revision` | Puede consultarse, pero requiere validación. |
| `preparacion_futura` | Se documenta para evolución, no para uso inmediato. |
| `bloqueado` | No debe activarse sin decisión explícita. |
| `deprecado` | No se recomienda, pero se conserva por trazabilidad. |

## 10. Reglas de seguridad para herramientas

```text
1. Toda herramienta que maneje datos personales requiere revisión.
2. Toda herramienta que use credenciales requiere control de acceso.
3. Toda herramienta con IA requiere evaluación de uso responsable.
4. Toda automatización futura requiere gobernanza.
5. Todo agente futuro queda bloqueado hasta decisión explícita.
6. Todo despliegue público requiere revisión de privacidad y contenido.
7. Toda exportación debe revisar si contiene datos sensibles.
8. Toda herramienta nueva debe registrarse antes de volverse estándar.
```
