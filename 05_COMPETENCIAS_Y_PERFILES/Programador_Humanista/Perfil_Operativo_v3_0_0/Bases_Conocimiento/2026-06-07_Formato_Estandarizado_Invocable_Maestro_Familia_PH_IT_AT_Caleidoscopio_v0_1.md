## 0. Propósito

Este formato define la estructura estándar para crear un **Invocable Maestro de Familia** dentro de la Base de Conocimiento Común PH-IT-AT-Caleidoscopio.

Un Invocable Maestro de Familia no es un invocable cualquiera. Es el artefacto rector que:

```text
define el propósito de una familia;
explica su fundamento;
organiza sus usos N1-N4;
declara sus relaciones con otras familias;
establece criterios para crear derivados;
orienta rutas situadas;
protege coherencia transdisciplinaria;
mantiene seguridad longitudinal;
sostiene trazabilidad;
devuelve aprendizaje al conocimiento común.
```

---

## 1. Diferencia entre familia, invocable maestro, invocable derivado y ruta situada

```text
Familia:
agrupación funcional de invocables relacionados por propósito, fundamento o uso.

Invocable maestro:
artefacto rector que gobierna la familia completa.

Invocable derivado:
artefacto especializado que nace del maestro solo cuando existe necesidad demostrada.

Ruta situada:
combinación adaptativa de familias e invocables según nivel, perfil, tarea, riesgo y contexto.
```

## 7. Cuándo usar este invocable maestro

```text
Usar cuando:
- se necesita activar una familia de invocables;
- se requiere orientar una ruta situada;
- se necesita decidir si crear un derivado;
- se busca alinear una tarea con el conocimiento común;
- se quiere transferir aprendizaje entre PH, IT y AT;
- se necesita revisar coherencia, seguridad o trazabilidad.
```

---

## 8. Cuándo no usar este invocable maestro

```text
No usar cuando:
- basta una instrucción simple;
- el usuario necesita solo un ejemplo puntual;
- la familia no está relacionada con la tarea;
- se pretende sustituir revisión humana;
- se busca automatizar una decisión sensible sin gobernanza;
- todavía no existe claridad suficiente sobre propósito, riesgo o producto esperado.
```

```text
[usuario / proceso / producto / riesgo / documentación]

Perfil o perfiles de entrada:
[común / PH / IT / AT / Caleidoscopio]

Producto esperado:
[describir]

Familias relacionadas:
[listar]

Restricciones:
[ética, seguridad, privacidad, tiempo, institución, formato, revisión humana]

Tarea:
1. Explica cómo esta familia aplica a la situación.
2. Indica qué otras familias deben considerarse por parentesco.
3. Recomienda una combinación de familias usando semáforo.
4. Indica si basta el invocable maestro o si se justifica un derivado.
5. Señala riesgos y criterios de seguridad longitudinal.
6. Propón evidencia mínima y registro de bitácora.
7. Indica cómo el aprendizaje retorna al conocimiento común.

No inventes datos.
No sustituyas revisión humana.
No ocultes incertidumbre.
No crees documentos nuevos si basta una sección, ejemplo, caso de uso, referencia lógica o deuda futura.
```

## 12. Recomendaciones semáforo

### Verde

Integrar de inmediato cuando:

```text
es necesario para comprender o ejecutar la tarea;
reduce riesgo básico;
mejora claridad;
fortalece trazabilidad;
no aumenta complejidad innecesaria.
```

### Amarillo

Registrar como consideración, expansión o deuda cuando:

```text
es valioso pero no imprescindible;
requiere más ejemplos;
depende de otra familia;
todavía no tiene suficiente uso real;
puede esperar sin poner en riesgo el proceso.
```

### Rojo

Pausar, escalar o requerir revisión fuerte cuando:

```text
hay datos sensibles;
hay evaluación de personas;
hay publicación externa;
hay automatización;
hay impacto institucional;
hay riesgo ético, legal, pedagógico o humano significativo;
la ruta excede el nivel de madurez disponible.
```

---

## 13. Criterios para crear invocables derivados

Un derivado solo se crea si cumple:

```text
tiene propósito propio;
atiende un caso recurrente;
no cabe como sección del maestro;
no basta como ejemplo;
no basta como caso de uso;
no basta como referencia lógica;
no basta registrarlo como deuda;
tiene ruta canónica;
tiene usuarios previstos;
tiene criterios de revisión humana;
mantiene trazabilidad con el maestro.
```

## 15. Seguridad longitudinal

### Antes

```text
verificar propósito;
identificar datos sensibles;
evaluar nivel de riesgo;
revisar perfil de entrada;
confirmar revisión humana;
evitar automatización prematura.
```

### Durante

```text
vigilar sesgos;
separar hechos de interpretaciones;
registrar incertidumbre;
mantener agencia humana;
documentar decisiones;
evitar expansión descontrolada.
```

### Después

```text
revisar salida;
actualizar trazabilidad;
registrar bitácora;
identificar retorno al conocimiento común;
registrar deuda;
decidir si se conserva como caso, ejemplo, ruta o derivado.
```
