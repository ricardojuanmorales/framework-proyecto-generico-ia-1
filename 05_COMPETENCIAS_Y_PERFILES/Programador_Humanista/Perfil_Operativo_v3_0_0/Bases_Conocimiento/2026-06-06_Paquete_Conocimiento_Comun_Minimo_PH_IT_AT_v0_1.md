## 0. Propósito

Este paquete establece el primer núcleo sustantivo reusable de la Base de Conocimiento Común PH-IT-AT para la Fase 2 Ronda 2 del Framework Genérico V4.1.1.

Su función es crear un mínimo compartido que pueda ser usado por:

- Programador Humanista, PH, como perfil piloto operativo.
- Investigador Transdisciplinario, IT, como perfil de metodología, evidencia, análisis, curaduría y publicación.
- Artista Transdisciplinario, AT, como perfil de mediación, experiencia, representación, accesibilidad y sentido humano.
- Caleidoscopio, como propiedad emergente de integración sistémica, no como agente autónomo.

Este documento no crea una nueva infraestructura. Pobla la infraestructura ya creada con conocimiento semilla, operativo, trazable y transferible.

## 4. Principios comunes PH-IT-AT

### 4.1 Principio de simetría operativa

PH, IT y AT no se organizan como jerarquía fija. Cada perfil puede iniciar, enriquecer, revisar o traducir conocimiento según su función.

```text
PH aporta implementación y estructura operativa.
IT aporta investigación, evidencia, método y trazabilidad.
AT aporta experiencia humana, mediación, accesibilidad y forma expresiva.
Caleidoscopio emerge de la interacción entre los tres.
```

### 4.2 Principio de transferencia reversible

Todo conocimiento que nazca desde PH debe poder ser:

```text
generalizado hacia conocimiento común;
reinterpretado por IT;
mediado por AT;
recombinado por Caleidoscopio;
devuelto a PH como mejora operativa.
```

### 4.3 Principio Markdown-first, JSON-compatible

El conocimiento se redacta primero en Markdown para legibilidad humana y luego se prepara para futura estructuración en JSON cuando exista necesidad real.

```text
Markdown para lectura, revisión y documentación humana.
JSON futuro para inventarios, tableros, importación, exportación e interoperabilidad.
```

### 4.4 Principio de invocabilidad humana

Un documento invocable no es un agente. Es una pieza documental que una persona puede usar para activar trabajo con claridad, contexto, límites y criterios de revisión.

### 4.5 Principio de seguridad longitudinal

La seguridad no se revisa solo al final. Acompaña todo el ciclo:

```text
creación;
ubicación;
uso;
invocación;
revisión;
expansión;
transferencia;
archivo;
publicación;
posible automatización futura.
```

### 4.6 Principio de suficiencia mínima

No se crean productos, carpetas, protocolos ni plantillas nuevas antes de que exista una necesidad operacional clara.

## 6. Unidades de conocimiento común mínimo

### UCC-001 — Gobernanza documental mínima

**Tipo:** conocimiento común  
**Uso:** ordenar creación, ubicación, revisión y actualización de documentos.

**Contenido semilla:**

Todo producto nuevo debe declarar:

```text
código documental;
versión;
fecha;
estado;
tipo de documento;
ruta canónica recomendada;
clasificación de conocimiento;
relación PH-IT-AT-Caleidoscopio;
nivel de seguridad;
estado de revisión humana.
```

**Transferencia:**

- PH usa estos campos para implementación y control de versiones.
- IT los usa para trazabilidad, evidencia y citabilidad.
- AT los usa para legibilidad, mediación y documentación humana.

**Seguridad:** no publicar documentos activos sin estado, versión y revisión humana.

---

### UCC-002 — Diferencia entre conocimiento común y conocimiento específico

**Tipo:** conocimiento común  
**Uso:** evitar que PH absorba funciones de IT y AT.

**Contenido semilla:**

```text
Conocimiento común:
aplica a PH, IT y AT.

Conocimiento específico:
pertenece a un perfil, herramienta, metodología, proceso o contexto particular.

Transferencia:
permite mover aprendizaje entre perfiles sin borrar su origen.

Activación caleidoscópica:
permite recombinar perspectivas cuando existe suficiente contenido base.
```

**Regla de oro:** PH puede ser piloto sin convertirse en centro jerárquico.

---

### UCC-003 — Ciclo mínimo de trabajo humano-máquina

**Tipo:** conocimiento común  
**Uso:** sostener sesiones cortas, enfocadas y verificables.

**Contenido semilla:**

```text
1. Activar contexto.
2. Delimitar objetivo.
3. Producir pieza mínima.
4. Verificar ruta y clasificación.
5. Revisar seguridad.
6. Registrar deuda visible.
7. Cerrar con continuidad.
```

**Aplicación N1:** cada sesión debe producir una pieza tangible o una decisión trazable.

**Transferencia:**

- PH convierte el ciclo en flujo operativo.
- IT lo convierte en método observable.
- AT lo convierte en experiencia humana clara.

---

### UCC-004 — Matriz mínima de trazabilidad

**Tipo:** conocimiento común  
**Uso:** conectar documentos sin duplicación ni pérdida de linaje.

| Elemento | Pregunta guía |
|---|---|
| Origen | ¿De qué documento, sesión o decisión nace? |
| Propósito | ¿Para qué existe? |
| Uso esperado | ¿Quién lo invoca y cuándo? |
| Ruta | ¿Dónde vive oficialmente? |
| Transferencia | ¿A qué perfiles alimenta? |
| Seguridad | ¿Qué riesgos o límites tiene? |
| Revisión | ¿Quién debe validarlo? |
| Deuda | ¿Qué queda pendiente? |

---

### UCC-005 — Rutas canónicas y referencias lógicas

**Tipo:** conocimiento común  
**Uso:** proteger el repositorio contra duplicación física.

**Contenido semilla:**

```text
Un documento vive en una ruta canónica.
Otros lugares pueden referirlo mediante referencias lógicas.
Los espejos deben ser referencias, no copias descontroladas.
Toda referencia lógica importante debe registrarse.
```

**Riesgo a vigilar:** crear copias paralelas con versiones divergentes.

---

### UCC-006 — Seguridad longitudinal básica

**Tipo:** conocimiento común  
**Uso:** revisar riesgos desde la creación hasta la expansión.

| Riesgo | Señal temprana | Mitigación mínima |
|---|---|---|
| Inflación documental | muchos documentos nuevos sin uso inmediato | crear solo piezas necesarias |
| Automatización prematura | deseo de activar agentes sin gobernanza | registrar como deuda futura |
| Confusión común/específico | PH aparece como centro absoluto | etiquetar transferencia |
| Pérdida de revisión humana | documento marcado activo sin validación | estado `pendiente_revision_humana` |
| Exposición de datos | datos sensibles en ejemplos | usar datos simulados o anonimizados |
| Dependencia técnica | herramienta se vuelve requisito innecesario | mantener Markdown legible |

---

### UCC-007 — Nivel N1 como alfabetización operativa

**Tipo:** conocimiento común  
**Uso:** definir el mínimo humano para comenzar.

**Contenido semilla:**

N1 no exige dominio técnico avanzado. Exige:

```text
comprender propósito;
ubicar documentos;
leer metadatos;
seguir guías humanas;
hacer preguntas claras;
reconocer límites;
registrar hallazgos y deudas;
revisar antes de publicar o automatizar.
```

**Transferencia:**

- PH: N1 aprende estructura y producción mínima.
- IT: N1 aprende evidencia, método y pregunta investigativa básica.
- AT: N1 aprende mediación, experiencia y comunicación humana básica.

---

### UCC-008 — Documento invocable mínimo

**Tipo:** conocimiento común  
**Uso:** preparar piezas que puedan activar trabajo sin convertirse en agentes.

**Estructura mínima:**

```text
nombre;
propósito;
cuándo usarlo;
cuándo no usarlo;
entradas requeridas;
salidas esperadas;
criterios de calidad;
criterios de seguridad;
relación con PH, IT, AT y Caleidoscopio;
estado de revisión.
```

**Regla:** toda invocación debe poder ser entendida por una persona sin depender de magia de máquina.

---

### UCC-009 — Transferencia PH-IT-AT

**Tipo:** transferencia PH-IT-AT  
**Uso:** convertir conocimiento de un perfil en aprendizaje reutilizable por otros.

| Desde | Hacia | Ejemplo de transferencia |
|---|---|---|
| PH | IT | bitácoras, trazabilidad, control de versiones, evidencias de producción |
| PH | AT | guías humanas, interfaces documentales, accesibilidad, narrativa operativa |
| IT | PH | metodologías, matrices de evidencia, criterios de evaluación |
| IT | AT | fundamentos, curaduría, contextos, criterios de interpretación |
| AT | PH | experiencia de usuario, representación visual, documentación sensible |
| AT | IT | mediaciones, observaciones cualitativas, lectura situada |

---

### UCC-010 — Activación caleidoscópica latente

**Tipo:** activación caleidoscópica  
**Uso:** dejar preparada la recombinación sin activarla prematuramente.

**Contenido semilla:**

El Caleidoscopio se activa cuando existen suficientes piezas para recombinar:

```text
conocimiento común;
conocimiento específico;
metodologías;
herramientas;
evidencia;
experiencia humana;
seguridad;
evaluación;
productos tangibles.
```

**Estado actual:** latente, no operativo autónomo.

**Regla:** el Caleidoscopio no sustituye perfiles, los entrelaza.

```text
Usa el Paquete de Conocimiento Común Mínimo PH-IT-AT v0.1 como base.
```

### 7.2 Invocación para revisar una pieza nueva

```text
Revisa esta pieza usando el Paquete de Conocimiento Común Mínimo PH-IT-AT v0.1.
Indica:
1. clasificación;
2. ruta canónica sugerida;
3. relación PH-IT-AT;
4. estado de seguridad;
5. deuda generada;
6. si puede transferirse a IT, AT o Caleidoscopio.
```

### 7.3 Invocación para evitar inflación documental

```text
Antes de crear un documento nuevo, determina si:
1. ya existe una pieza que puede ampliarse;
2. basta una referencia lógica;
3. debe registrarse como deuda;
4. sí se justifica una nueva pieza.
```
